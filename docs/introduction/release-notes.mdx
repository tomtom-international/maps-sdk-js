## Version status

This table shows the status of each version of `@tomtom-org/maps-sdk` and its dates. The [support window](./versioning-and-support-policy.mdx#support-window) says which fixes each status gets. Releases in Public Preview follow [their own rules](./versioning-and-support-policy.mdx#releases-before-100-and-plugins) instead.

| Version | Status | Released | End of life |
| --- | --- | --- | --- |
| 1.0.0 release candidates, from 1.0.0-rc.0 | Public Preview. Only the latest one gets fixes. | From October 6, 2026 | When 1.0.0 ships |
| 0.x, up to 0.64.0 | Public Preview. Fixes ship in the release candidates, not in a new 0.x release. | Up to October 4, 2026 | When 1.0.0 ships |

To move from a 0.x release, follow [Upgrading to 1.0](../guides/migration/upgrading-to-1-0.mdx).

## Understanding release versioning

The SDK follows semantic versioning. A major release can break your code, a minor adds features and a patch fixes bugs. The [versioning and support policy](./versioning-and-support-policy.mdx) says what counts as a breaking change, how much notice a deprecation gets and how long each major gets fixes.

Until 1.0.0 ships, `npm install @tomtom-org/maps-sdk` installs the latest release candidate.

## Documentation of earlier versions

These pages describe the latest release. If your project uses an earlier release, read its documentation in the [documentation archive](https://tomtom-international.github.io/maps-sdk-js/).

- The archive holds the guides and the API reference of each release, as they shipped with it.
- It shows the most recent releases. An older release links to its `v<version>` tag on [GitHub](https://github.com/tomtom-international/maps-sdk-js/tags), which holds the same documentation as files.
- The examples always run the latest release, so the archive leaves them out.

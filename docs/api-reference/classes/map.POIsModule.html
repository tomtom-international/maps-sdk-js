    Class POIsModule

    A module that controls the points of interest the map style displays.

    It manages the built-in POI layer of the vector map, so you can show or hide POIs and filter them by category. POIs are already part of the map style and include businesses, landmarks and other points of interest.

    Remarks

    This module owns whether the style's POIs are shown, which categories, any custom icon a category is drawn with, and their look (size, label colours and zoom thresholds). The micro markers show or hide on their own (microMarkers.visible), never while the POIs are hidden. See Who owns what. poisKnobCatalogue lists the settings of its configuration a knob holds.

    Features:

    • Toggle POI visibility on/off
    • Filter by POI categories or category groups
    • Custom icons per POI category (POIIconConfig)
    • Event handling for POI interactions
    • Based on vector tile data in the map style

    POI categories:

    • Individual categories (e.g., RESTAURANT, HOTEL_OR_MOTEL, PARKING_GARAGE)
    • Category groups (e.g., FOOD_DRINKS_GROUP, SHOPPING_GROUP, TRANSPORTATION_GROUP)

    Difference from PlacesModule:

    • POIsModule: Controls existing POIs in the map style
    • PlacesModule: Displays custom place data from Search API or other sources

    Example

    Basic usage:

    import { POIsModule } from '@tomtom-org/maps-sdk/map';

    // Get module
    const poisModule = await POIsModule.get(map);

    // Toggle visibility
    poisModule.setVisible(false);
    poisModule.setVisible(true);

    Example

    Filter specific categories:

    // Show only restaurants and hotels
    poisModule.updateConfig({
      filters: { categories: { show: 'only', values: ['RESTAURANT', 'HOTEL_OR_MOTEL'] } },
    });

    // Hide parking garages
    poisModule.updateConfig({
      filters: { categories: { show: 'all-except', values: ['PARKING_GARAGE', 'OPEN_CAR_PARKING_AREA'] } },
    });

    // Show every POI again
    poisModule.updateConfig({ filters: undefined });

    Example

    Filter using category groups:

    // Show only food and shopping POIs
    poisModule.updateConfig({
      filters: { categories: { show: 'only', values: ['FOOD_DRINKS_GROUP', 'SHOPPING_GROUP'] } },
    });

    Example

    Custom icons per category, shared with the places a PlacesModule shows:

    const categoryIcons = [
      { id: 'RESTAURANT', image: restaurantSvg },
      { id: 'HOTEL_OR_MOTEL', image: '/icons/hotel.png', pixelRatio: 2 },
    ];
    poisModule.updateConfig({ icon: { categoryIcons } });
    searchResults.updateConfig({ icon: { categoryIcons } });

    // The style's own icons again
    poisModule.updateConfig({ icon: undefined });

    Example

    Event handling:

    pois.events.on('click', (feature, lngLat) => {
      console.log('Clicked POI:', feature.properties.name);
      console.log('Category:', feature.properties.category);
    });

    Accessors

    events

    • get events(): CombinedEvents<POIsModuleFeature, POIsModuleConfig, never>

      The events of user interactions with POIs.

      Returns CombinedEvents<POIsModuleFeature, POIsModuleConfig, never>

      The module's events, with on / off for handlers and where for scoping.

      Remarks

      Supported events:

      • click: User clicks on a POI
      • contextmenu: User right-clicks on a POI
      • hover: Mouse enters a POI
      • long-hover: Mouse hovers over POI for extended time

      Event feature properties:

      • id: Unique POI identifier
      • name: POI name in native language
      • category: POI category
      • group: Category group
      • priority: Importance level (lower = more important)

      Example

      pois.events.on('click', (feature, lngLat) => {
        console.log('POI:', feature.properties.name);
        console.log('Category:', feature.properties.category);
        console.log('ID:', feature.properties.id);
      });

      pois.events.on('hover', (feature) => {
        showTooltip(feature.properties.name);
      });

    sourceAndLayerIDs

    • get sourceAndLayerIDs(): Record<keyof SOURCES_WITH_LAYERS, SourceWithLayerIDs>

      The MapLibre source and layer IDs of all sources this module creates and manages.

      Returns Record<keyof SOURCES_WITH_LAYERS, SourceWithLayerIDs>

      A record mapping each source name to its MapLibre source ID and an array of the IDs of that source's layers.

      Remarks

      Use these IDs to:

      • Directly manipulate layers using MapLibre's native API
      • Identify which layers on the map belong to this module
      • Set layer ordering or positioning relative to other layers
      • Access source or layer properties through MapLibre methods

      Example

      const ids = myModule.sourceAndLayerIDs;
      console.log(ids);
      // {
      //   mySource: {
      //     sourceID: 'my-source-id',
      //     layerIDs: ['layer-1', 'layer-2']
      //   }
      // }

      // Use with MapLibre API
      const map = myModule.mapLibreMap;
      ids.mySource.layerIDs.forEach(layerId => {
        map.setLayoutProperty(layerId, 'visibility', 'visible');
      });

    Methods

    applyConfig

    • applyConfig(config: POIsModuleConfig | undefined): void

      Applies a configuration to this module.

      The module updates its behaviour and appearance to match. It stores the configuration and reapplies it automatically when the map style changes.

      Parameters

      • config: POIsModuleConfig | undefined

        The configuration to apply. Pass undefined to reset it to the default values.

      Returns void

      Remarks

      The given configuration replaces the current one rather than being merged into it. To change one part of it, use updateConfig.

      Example

      // Apply a new configuration
      myModule.applyConfig({ visible: true, color: '#E63312' });

      // Reset to default configuration
      myModule.applyConfig(undefined);

      See

      • resetConfig for a convenience method to reset configuration
      • getConfig to retrieve the current configuration

      Inherited from AbstractStyleOwnedMapModule.applyConfig

    getConfig

    • getConfig(): NonNullable<POIsModuleConfig> | undefined

      Returns a shallow copy of the current module configuration, or undefined if none is applied.

      Returns NonNullable<POIsModuleConfig> | undefined

      A shallow copy of the current configuration, or undefined. It is a copy so that you can't modify the internal state by accident.

      Remarks

      Only the top-level properties are copied. Nested objects and arrays still reference the original configuration. This is enough for most use cases, but keep it in mind with complex configurations.

      Example

      // Apply a configuration
      myModule.applyConfig({ visible: true, color: '#E63312' });

      // Later, retrieve the current configuration
      const currentConfig = myModule.getConfig();
      console.log(currentConfig); // { visible: true, color: '#E63312' }

      // When no config is applied
      myModule.resetConfig();
      console.log(myModule.getConfig()); // undefined

      See

      • applyConfig to modify the configuration
      • resetConfig to clear the configuration

    resetConfig

    • resetConfig(): void

      Resets this module's configuration to its default values.

      It clears any applied configuration and restores the module to its initial state, the same as calling applyConfig(undefined).

      Returns void

      Remarks

      The module then behaves as if no configuration was ever applied. Any custom settings, styling or behaviour changes are replaced with default values.

      Example

      // Apply some configuration
      myModule.applyConfig({ visible: true, color: '#E63312' });

      // Later, reset to defaults
      myModule.resetConfig();

      See

      • applyConfig to apply a new configuration
      • getConfig to retrieve the current configuration before resetting

    updateConfig

    • updateConfig(partial: Partial<NonNullable<CFG>>): void

      Changes part of the configuration and keeps the rest.

      The given properties are laid over the current configuration one level deep, so a nested object you pass replaces the one that was there. The result is applied with applyConfig. This works the same on every module, whatever its applyConfig does with a whole configuration.

      Parameters

      • partial: Partial<NonNullable<CFG>>

        The properties to change.

      Returns void

      Example

      routing.applyConfig({ displayUnits: { distance: { type: 'imperial_us' } }, color: '#0a3653' });
      routing.updateConfig({ color: '#c2185b' }); // displayUnits stays imperial

      See

      applyConfig to apply a whole configuration

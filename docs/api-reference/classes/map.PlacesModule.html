    Class PlacesModule

    A map module that displays and manages place markers.

    It displays location markers (pins) on the map for points of interest, search results or custom locations, with various marker styles, custom icons, text labels and interactive events.

    Remarks

    Features:

    • Marker types (PlacesMarkerType): pins, circles, base-map POI look-alikes and clustered pins
    • One colour for the module's own drawing (PlacesModuleConfig.color)
    • Custom icons per POI category
    • Text labels with styling options
    • Data-driven styling via MapLibre expressions
    • Interactive events (click, hover, etc.)
    • Support for custom feature properties
    • Entry points of places, for all of them or only hovered or clicked ones (opt-in)

    Common use cases:

    • Search result visualization
    • Custom location markers
    • Store locators
    • Delivery/pickup points
    • Saved locations display

    Example

    // Create places module with pin markers
    const placesModule = await PlacesModule.create(map, {
      icon: {
        categoryIcons: []
      },
      label: {
        title: (place) => place.properties.poi?.name || 'Unknown'
      },
      markerType: 'pin'
    });

    // Display places from search
    await placesModule.show(searchResults);

    // Handle clicks
    placesModule.events.on('click', (feature) => {
      console.log('Clicked:', feature.properties);
    });

    placesModule.events.on('hover', (feature) => {
      showTooltip(feature.properties.poi?.name);
    });

    • get sourceAndLayerIDs(): Record<keyof SOURCES_WITH_LAYERS, SourceWithLayerIDs>

      The MapLibre source and layer IDs of all sources this module creates and manages.

      Returns Record<keyof SOURCES_WITH_LAYERS, SourceWithLayerIDs>

      A record mapping each source name to its MapLibre source ID and an array of the IDs of that source's layers.

      Remarks

      Use these IDs to:

      • Directly manipulate layers using MapLibre's native API
      • Identify which layers on the map belong to this module
      • Set layer ordering or positioning relative to other layers
      • Access source or layer properties through MapLibre methods

      Example

      const ids = myModule.sourceAndLayerIDs;
      console.log(ids);
      // {
      //   mySource: {
      //     sourceID: 'my-source-id',
      //     layerIDs: ['layer-1', 'layer-2']
      //   }
      // }

      // Use with MapLibre API
      const map = myModule.mapLibreMap;
      ids.mySource.layerIDs.forEach(layerId => {
        map.setLayoutProperty(layerId, 'visibility', 'visible');
      });

    getConfig

    • getConfig(): NonNullable<PlacesModuleConfig> | undefined

      Returns a shallow copy of the current module configuration, or undefined if none is applied.

      Returns NonNullable<PlacesModuleConfig> | undefined

      A shallow copy of the current configuration, or undefined. It is a copy so that you can't modify the internal state by accident.

      Remarks

      Only the top-level properties are copied. Nested objects and arrays still reference the original configuration. This is enough for most use cases, but keep it in mind with complex configurations.

      Example

      // Apply a configuration
      myModule.applyConfig({ visible: true, color: '#E63312' });

      // Later, retrieve the current configuration
      const currentConfig = myModule.getConfig();
      console.log(currentConfig); // { visible: true, color: '#E63312' }

      // When no config is applied
      myModule.resetConfig();
      console.log(myModule.getConfig()); // undefined

      See

      • applyConfig to modify the configuration
      • resetConfig to clear the configuration

      Inherited from AbstractDataOwnedMapModule.getConfig

    setEventState

    • setEventState(options: SetEventStateOptions): void

      Puts an event state on one of the shown features, as a user interaction would.

      Parameters

      • options: SetEventStateOptions

      Returns void

      Remarks

      The state is what the module's own layers draw (place pins and entry points, route outlines, geometries, details-module incidents, area-analytics cells), what layers of yours read with ['get', 'eventState'], and what getEventStates returns. It lasts as long as the shown feature does, through setVisible, style and configuration changes, but not a new show, a clear or a setStyle with resetState.

      Example

      module.setEventState({ id: feature.properties.id, state: 'click' });

      // Hover a second one without taking the hover off the first
      module.setEventState({ index: 2, state: 'hover', mode: 'add' });

    show

    • show(places: ShownPlaces): Promise<void>

      Displays the given places on the map.

      Parameters

      • places: ShownPlaces

        The places to display, as a single Place, an array of Places or a Places FeatureCollection.

      Returns Promise<void>

      Remarks

      Behaviour:

      • Replaces any previously shown places, and never merges with them.
      • Drops the event states of the places it replaces, even of a place shown again under the same id. An event state lives on the shown feature, so re-select with setEventState by id. Places that carry properties.eventState, such as getShown().places, keep theirs.
      • Drops the shown connections (see PlaceConnectionDisplay).
      • Applies the current module styling configuration.
      • Generates labels if the label config is set.
      • Waits for the module to be ready before displaying.

      Data sources:

      • TomTom Search API results
      • Custom place objects matching the Place interface
      • GeoJSON Point features

      ShownPlaces names the places services whose results are not places, and what shows them.

      Example

      Display search results:

      import { discoverPlaces } from '@tomtom-org/maps-sdk/services';

      const results = await discoverPlaces({ query: 'coffee' });
      await placesModule.show(results);

      Example

      Display single place:

      await placesModule.show({
        type: 'Feature',
        geometry: { type: 'Point', coordinates: [4.9041, 52.3676] },
        properties: {
          address: { freeformAddress: 'Amsterdam' },
          poi: { name: 'Amsterdam Central' }
        }
      });

      Example

      Display multiple places:

      await placesModule.show([place1, place2, place3]);

    showConnections

    • showConnections(connections: PlaceConnectionDisplay[]): Promise<void>

      Displays connection lines between pairs of places on the map.

      Parameters

      • connections: PlaceConnectionDisplay[]

        The connections to render. Each has a from and to endpoint, as a Place or as the id of a place this module currently shows.

      Returns Promise<void>

      Remarks

      • Replaces any previously shown connections.
      • Silently skips connections whose id doesn't resolve against the currently shown places.
      • If the module config sets connections.label.title, the string it returns is rendered as a label along each line, slightly offset to the side. Otherwise, no label is shown.
      • show() and clear() clear the connections first, since their endpoints may no longer be on the map.

      Example

      const places = await PlacesModule.create(map, {
        connections: {
          label: { title: (c) => `${c.distanceMeters} m` }
        }
      });
      await places.show([station, ...cafes]);
      await places.showConnections(
        cafes.features.map((cafe) => ({
          from: station.id,
          to: cafe.id,
          distanceMeters: Math.round(cafe.properties.distance ?? 0),
        })),
      );

    Class StylingFoundationsModule

    The foundations of the whole map's look, with sizes across every part of the style, the ten map colours and the accent, the projection and the sky.

    It is the tier between showing or hiding a part of the map and hand-editing MapLibre layers. Every adjustable thing is a knob with a stable id, a kind, a range and a default read from the loaded style. The ids form the StylingFoundationsKnobId union, and stylingFoundationsKnobCatalogue lists each one's kind, range and description as data, with no map needed to read it. setKnob, getKnob and resetKnob set, read and unset a knob by its id, as on every module.

    Remarks

    The catalogue's appliesTo says which styles a knob works on. any-style knobs (sizes, widths) scale whatever the style already does, so they survive style-version bumps. A zoom ramp has each stop's output scaled, and any other expression E becomes ["*", 1.3, E]. tomtom-styles knobs (the map colours) reach their layers through the TomTom styles this SDK version is verified against. On a style layer they do not recognise, setting one warns once and does nothing.

    After every setStyle that carries state over, the settings are re-applied on top of whatever the other modules restored. A clean switch (resetState: true) drops them.

    Each part of the map's look belongs to its own module. POIsModule sizes and colours the POIs, TrafficFlowModule and TrafficIncidentsModule the traffic lines, TerrainModule the hillshade, and BaseMapModule shows and hides the layer groups and the road markings within them. The sizes here compose with theirs, so labels.sizeFactor and the POIs' sizeFactor multiply on the POI labels.

    Example

    import { getKnob, setKnob, StylingFoundationsModule, stylingFoundationsKnobCatalogue } from '@tomtom-org/maps-sdk/map';

    const styling = await StylingFoundationsModule.get(map);
    setKnob(styling, stylingFoundationsKnobCatalogue, 'labels.sizeFactor', 1.2);
    setKnob(styling, stylingFoundationsKnobCatalogue, 'colors.water', '#7cc4e8');

    // The catalogue as data, and each knob's value in force:
    for (const knob of stylingFoundationsKnobCatalogue) {
      console.log(knob.id, knob.kind, knob.range, getKnob(styling, stylingFoundationsKnobCatalogue, knob.id));
    }

    // Serializable, diffable, re-applicable:
    const saved = styling.getConfig();
    styling.resetConfig();
    styling.applyConfig(saved);

    sourceAndLayerIDs

    • get sourceAndLayerIDs(): Record<keyof SOURCES_WITH_LAYERS, SourceWithLayerIDs>

      The MapLibre source and layer IDs of all sources this module creates and manages.

      Returns Record<keyof SOURCES_WITH_LAYERS, SourceWithLayerIDs>

      A record mapping each source name to its MapLibre source ID and an array of the IDs of that source's layers.

      Remarks

      Use these IDs to:

      • Directly manipulate layers using MapLibre's native API
      • Identify which layers on the map belong to this module
      • Set layer ordering or positioning relative to other layers
      • Access source or layer properties through MapLibre methods

      Example

      const ids = myModule.sourceAndLayerIDs;
      console.log(ids);
      // {
      //   mySource: {
      //     sourceID: 'my-source-id',
      //     layerIDs: ['layer-1', 'layer-2']
      //   }
      // }

      // Use with MapLibre API
      const map = myModule.mapLibreMap;
      ids.mySource.layerIDs.forEach(layerId => {
        map.setLayoutProperty(layerId, 'visibility', 'visible');
      });

    applyConfig

    • applyConfig(config: StylingFoundationsModuleConfig | undefined): void

      Applies a configuration to this module.

      The module updates its behaviour and appearance to match. It stores the configuration and reapplies it automatically when the map style changes.

      Parameters

      • config: StylingFoundationsModuleConfig | undefined

        The configuration to apply. Pass undefined to reset it to the default values.

      Returns void

      Remarks

      The given configuration replaces the current one rather than being merged into it. To change one part of it, use updateConfig.

      Example

      // Apply a new configuration
      myModule.applyConfig({ visible: true, color: '#E63312' });

      // Reset to default configuration
      myModule.applyConfig(undefined);

      See

      • getConfig to retrieve the current configuration

    exportStyle

    • exportStyle(): StyleSpecification

      Exports the style as currently rendered, with every knob applied, as a MapLibre style specification to save, diff or serve yourself.

      Returns StyleSpecification

      Remarks

      It includes whatever the SDK's data modules (places, routes) have on the map. Its tile URLs carry the API key the map was created with, so strip or rotate the key before publishing.

    getConfig

    • getConfig(): NonNullable<StylingFoundationsModuleConfig> | undefined

      Returns a shallow copy of the current module configuration, or undefined if none is applied.

      Returns NonNullable<StylingFoundationsModuleConfig> | undefined

      A shallow copy of the current configuration, or undefined. It is a copy so that you can't modify the internal state by accident.

      Remarks

      Only the top-level properties are copied. Nested objects and arrays still reference the original configuration. This is enough for most use cases, but keep it in mind with complex configurations.

      Example

      // Apply a configuration
      myModule.applyConfig({ visible: true, color: '#E63312' });

      // Later, retrieve the current configuration
      const currentConfig = myModule.getConfig();
      console.log(currentConfig); // { visible: true, color: '#E63312' }

      // When no config is applied
      myModule.resetConfig();
      console.log(myModule.getConfig()); // undefined

      See

      • applyConfig to modify the configuration
      • resetConfig to clear the configuration

    setMapColors

    • setMapColors(colors: MapColors): void

      Recolours the whole base map with up to ten semantic colours in one call, and sets accent, the default colour of routes, geometries and places (TomTomMap.mapColors).

      The ten are the style themes' Foundations palette, each listed with what it reaches under MapColorName. Partial objects are fine. The colours you leave out stay as they are, except on the mono styles, which derive the other nine from land as their theme does. There, the theme's own formulas re-derive them from the given land.

      Parameters

      • colors: MapColors

        The colours to set, as CSS colour strings.

      Returns void

      Remarks

      Each colour re-derives every shade the style built from it, such as a trunk variant, an outline or a tunnel, at the style's own HSL offset, so those relationships survive the recolour. The colours are also the colors.* knobs, so getKnob, resetKnob and settings persistence apply.

      The offsets come from the loaded style, which makes a palette a recolour and not an inversion. Dark land over streetLight pushes the derived shades to the ends of their range, so switch to streetDark first.

      Throws

      RangeError for a value that is not a colour; Error for an unknown colour name.

      Example

      styling.setMapColors({ land: '#f3f5f7', water: '#accbe2', roadMajor: '#a1b8ce', label: '#364659' });
      resetKnob(styling, stylingFoundationsKnobCatalogue, 'colors.roadMajor'); // one colour back to the style
      styling.setMapColors(deriveMapColors(['#0b2a3a', '#0fa8c8', '#f6efe3'])); // map-theme plugin assigns the roles

    updateConfig

    • updateConfig(partial: Partial<NonNullable<CFG>>): void

      Changes part of the configuration and keeps the rest.

      The given properties are laid over the current configuration one level deep, so a nested object you pass replaces the one that was there. The result is applied with applyConfig. This works the same on every module, whatever its applyConfig does with a whole configuration.

      Parameters

      • partial: Partial<NonNullable<CFG>>

        The properties to change.

      Returns void

      Example

      routing.applyConfig({ displayUnits: { distance: { type: 'imperial_us' } }, color: '#0a3653' });
      routing.updateConfig({ color: '#c2185b' }); // displayUnits stays imperial

      See

      applyConfig to apply a whole configuration

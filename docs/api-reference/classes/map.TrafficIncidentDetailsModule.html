    Class TrafficIncidentDetailsModule

    Renders traffic incidents returned by trafficIncidentDetails() on the map.

    Use this module when you fetch incidents through the Incident Details service and want to display them as a developer-controlled overlay. TrafficIncidentsModule is the vector-tile alternative. It is hidden in the default style, so this module renders on its own without collision. If you've enabled it elsewhere in your app, hide it again before using this module to avoid double-rendering.

    Rendering approach

    The module draws 7–8 layers: 4 to 5 line layers (optional highlight-halo, outline, solid inner, direction chevron, pattern inner) and 3 symbol layers (incident marker, jam marker with delay text, closed-road marker). Per-magnitude styling uses match expressions on magnitudeOfDelay inside a single layer instead of one layer per magnitude. Colours come from the loaded style's incident layers (see ./util/readIncidentPalette), with built-in defaults when absent. They are read again whenever a traffic.incidents.*Color styling knob recolours them. Direction renders as a tiled line-pattern (a chevron sprite registered at init) instead of the vector-tile module's per-feature roads-arrow symbol. The pattern is continuous, so it reads on short jams and at planning zooms (z12+), while the per-feature symbol only activates at z15+.

    Focus and highlight

    setFocus writes MapLibre feature-state focused=true|false on each rendered incident. The default highlight widens the focused subset and paints an outline beneath it (black on light map styles, white on dark). Unfocused incidents are unchanged. A hovered or clicked incident (its eventState, see setEventState) draws the same highlight. To override or disable it, use the highlight config. With highlight: false, setFocus still writes feature-state but no halo layer or width pop is emitted, so you can drive your own styling off feature-state.focused and eventState.

    API limitations

    The Incident Details REST API returns a feature list, not a rendering-ready tile. Several tags that the vector-tile pipeline injects per-feature are absent:

    • Road classification (road_category, road_subcategory). The vector-tile pipeline scales line width and offset by road class (motorway wider than street, stripe placed alongside the road on one carriageway). Without it, per-road-class geometry becomes a guess, so the module renders every incident as a uniform stripe centred on the road, with no offset.
    • Traffic-direction side (left_hand_traffic). It only matters with road-class-driven offset, so it is irrelevant here.
    • Declutter priority (display_class). The vector-tile pipeline hides low-priority incidents at low zooms. The module shows everything above its layer's minzoom, and the icons of shorter delays only from a higher zoom.
    • Endpoint restriction (point_type). The vector-tile pipeline limits jam and closed-road icons to line endpoints. The module renders them on every matching feature.
    • Secondary cause (icon_category_1). The vector-tile pipeline layers a cause icon (e.g. accident) over the jam icon. The module shows only the primary category.

    For full per-road-class visual fidelity, use TrafficIncidentsModule instead.

    Known limitations

    • Overlapping incidents. When multiple incidents share the same point or stack along the same road segment, MapLibre's symbol collision culling keeps only the highest-sort-key feature. Culled features are also invisible to queryRenderedFeatures, so hover and click cannot reach them. To surface multiple incidents at one location, query the source data directly (the FeatureCollection you passed to show) rather than relying on render-time hit-testing.

    Example

    Fetch and render incidents for Amsterdam:

    import { TomTomConfig } from '@tomtom-org/maps-sdk/core';
    import { TomTomMap, TrafficIncidentDetailsModule } from '@tomtom-org/maps-sdk/map';
    import { trafficIncidentDetails } from '@tomtom-org/maps-sdk/services';

    TomTomConfig.instance.put({ apiKey: '<API_KEY>' });

    const map = new TomTomMap({ mapLibre: { container: 'map', center: [4.9, 52.37], zoom: 13 } });

    const incidentDetailsModule = await TrafficIncidentDetailsModule.create(map);
    const result = await trafficIncidentDetails({
        bbox: [4.85, 52.34, 4.95, 52.40],
        timeValidityFilter: ['present'],
    });
    await incidentDetailsModule.show(result);

    // Highlight a subset.
    incidentDetailsModule.setFocus([result.features[0].properties.id]);

      const map = myModule.mapLibreMap;
      ids.mySource.layerIDs.forEach(layerId => {
        map.setLayoutProperty(layerId, 'visibility', 'visible');
      });

    Class MapEffects

    Practical post-processing for a TomTomMap, with effects computed from the rendered map's own pixels rather than its style. They therefore work on every style, survive every style release, and cannot be reproduced by editing the style at all.

    Remarks

    Public Preview until the plugin's 1.0.0 release.

    Every effect is named by the problem it solves, and off by default:

    • bloom - Emphasis on dark and driving styles. Lit roads, traffic tubes and route lines glow.
    • glare - Lights that read as lights. The colours you name, by default the major roads, cast streaks as lamps do through a star filter or an anamorphic lens.
    • grade (brightness, contrast, saturation) and tint - Muting the base map so a data overlay reads first.
    • fog - Depth. The rim is blurred and washed towards the colour of the air, fog.color, which follows the map's light/dark theme while unset.
    • edge blur - Focus. The rim is blurred and keeps its colour, so it reads as a lens rather than as distance.
    • depth of field - Depth on a tilted map. One band of distance stays sharp and the rest defocuses, worked out from the camera's pitch and field of view, so a flat map ends it.
    • vignette - Focus too, by darkening or lightening the edges.

    Effects render live as layers over the map canvas, and are composited the same way into capture, so what is captured is what was on screen. From the bottom, the layers are a WebGL2 chain that also runs your own passes from addPass, the glare and a bloom scoped with bloom.only, an unscoped bloom as a small canvas blended in screen mode, and the CSS overlays. Your own 2D layers from addLayer take a place among the overlays. HTML markers, popups and the map's controls sit above every effect.

    The effects draw on the map's render event, in the same frame as the map, so the map needs no preserveDrawingBuffer. Adding a pass, or setting a knob of bloom, the glare or the depth of field, asks the map for one frame to draw in. The CSS overlays need none.

    effectKnobCatalogue lists every knob as static data, the way stylingFoundationsKnobCatalogue lists the SDK's styling knobs. Each id is its path into MapEffectsConfig. The SDK's setKnob, setKnobs, getKnob and resetKnob set, read and unset knobs by id, as on a map module.

    Example

    import { setKnob, setKnobs } from '@tomtom-org/maps-sdk/map';
    import { effectKnobCatalogue, MapEffects } from '@tomtom-org/maps-sdk-plugin-map-effects';

    const effects = new MapEffects(map);
    // The data-viz muting half: a dim, desaturated base under your own layers.
    effects.applyConfig({ grade: { saturation: 0.4, brightness: 0.85 }, tint: { opacity: 0.15 } });
    // Night-driving emphasis on a dark style, keeping the rest:
    setKnobs(effects, effectKnobCatalogue, { 'bloom.intensity': 0.5, 'bloom.threshold': 0.6 });
    setKnob(effects, effectKnobCatalogue, 'vignette.intensity', -0.4);

    const poster = await effects.capture({ pixelRatio: 3 });

    addLayer

    • addLayer(layer: MapEffectsLayer): void

      Draws a 2D canvas layer of your own between the overlay effects, and in capture in the same place. Layers in one placement stack in the order they were added.

      Parameters

      • layer: MapEffectsLayer

      Returns void

      Remarks

      A layer redraws with the map. If it changes on its own, as film grain does, ask for frames with map.mapLibreMap.triggerRepaint(). A layer needs no WebGL2 context and reads no canvas.

      Throws

      Error when the layer has no id; RangeError for an unknown placement.

      Example

      // A paper texture under the tint and the vignette, which then work on the paper too.
      effects.addLayer({
          id: 'paper',
          placement: 'after-edgeBlur',
          draw: (context, { width, height }) => {
              context.globalAlpha = 0.25;
              context.fillStyle = context.createPattern(paper, 'repeat') ?? 'transparent';
              context.fillRect(0, 0, width, height);
          },
      });

    addPass

    • addPass(pass: MapEffectsPass): void

      Runs a GPU pass of your own in the effects chain, ahead of every overlay effect, and in capture as on screen. Passes run in the order they were added, within their placement.

      Parameters

      • pass: MapEffectsPass

      Returns void

      Remarks

      A pass redraws with the map. If its uniforms change on their own, as in a time-driven animation, ask for frames with map.mapLibreMap.triggerRepaint(). A pass that shifts hues runs before the bloom's and the glare's colour keys too, so a bloom.only or glare.only scope may need a wider bloom.onlyTolerance or glare.onlyTolerance.

      Throws

      Error when the pass has no id or its shader does not compile, with the compiler's log; RangeError for an unknown placement, or for more than 15 textures or one named uSource. A shader is checked only while there is a WebGL2 context: without one no pass runs and the plugin warns once, and after a lost one it is checked on restore.

      Example

      effects.addPass({
          id: 'posterise',
          fragment: `uniform float uLevels;
              void main() {
                  vec4 colour = texture(uSource, vUv);
                  fragColor = vec4(floor(colour.rgb * uLevels) / uLevels, colour.a);
              }`,
          uniforms: { uLevels: 5 },
      });

    applyConfig

    • applyConfig(config: MapEffectsConfig): void

      Replaces the whole configuration. An empty object turns everything off.

      Parameters

      • config: MapEffectsConfig

      Returns void

      Remarks

      Use it, and updateConfig, for a look your code writes, such as a use case swapped in whole: as on a map module, the type is the check, and the values are not checked again. For values held as data, the SDK's setKnobs checks each against the catalogue and sets them by id.

      Example

      effects.applyConfig({ grade: { saturation: 0.4, brightness: 0.85 }, tint: { opacity: 0.15 } });

    capture

    • capture(options?: CaptureOptions): Promise<HTMLCanvasElement>

      Renders the current view, with its effects, into a canvas, optionally at a higher pixel ratio for print. The map is re-rendered at that ratio (never resampled), read back once every tile is drawn or 15 seconds have passed, whichever comes first, and then set back to the ratio it had.

      Parameters

      • Optionaloptions: CaptureOptions

      Returns Promise<HTMLCanvasElement>

      Remarks

      • Viewers cannot download from a sandboxed page, so hand the canvas to your own upload or toBlob flow.
      • It rejects when the frame fails to draw, such as with a pass texture from another origin that was loaded without CORS, and with a RangeError for a pixelRatio that isn't a positive number.

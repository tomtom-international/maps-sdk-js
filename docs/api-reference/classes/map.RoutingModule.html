    Class RoutingModule

    The map module that displays and manages routes.

    It draws route lines, alternative routes, turn-by-turn guidance and waypoints, and works with the TomTom Routing API.

    Remarks

    Features:

    • Display route lines with customizable styling
    • Show alternative routes with different styling
    • Waypoint pins per role (origin, numbered or lettered stops, destination), with hover and click events
    • Turn-by-turn guidance instructions
    • Route section highlighting
    • Distance and duration information
    • Several routes at once

    Common use cases:

    • Turn-by-turn navigation displays
    • Route planning and comparison
    • Multi-stop route optimization
    • Interactive route editing
    • Fleet management route visualization

    Example

    // Create the module
    const routingModule = await RoutingModule.create(map, {
      displayUnits: {
        distance: { type: 'metric' }
      }
    });

    // Calculate and display a route
    const result = await calculateRoute({
      apiKey: 'your-api-key',
      locations: [
        [4.9041, 52.3676],  // Amsterdam
        [4.4777, 51.9244]   // Rotterdam
      ],
      travelMode: 'car',
      costModel: { routeType: 'fast' }
    });

    await routingModule.showRoutes(result);

    events

    • get events(): RoutingEvents

      The routing module's events, in one interface.

      events itself covers every route feature and the module's lifecycle events. Each named scope below covers one part of a route, and you can narrow any of them further with where().

      routing.events.mainLines.on('click', (route) => { ... });
      routing.events.waypoints.on('hover', (waypoint) => { ... });

      // Only the selected route's tunnels, with their own hover cursor:
      routing.events.tunnels
          .where((section) => section.properties.routeState === 'selected', { cursorOnHover: 'help' })
          .on('click', showTunnel);

      const unsub = routing.events.on('config-change', (config) => { ... });
      routing.events.on('shown-features', (features) => {
        if ('routes' in features) { ... }
      });
      unsub();

      Returns RoutingEvents

    sourceAndLayerIDs

    • get sourceAndLayerIDs(): Record<keyof SOURCES_WITH_LAYERS, SourceWithLayerIDs>

      The MapLibre source and layer IDs of all sources this module creates and manages.

      Returns Record<keyof SOURCES_WITH_LAYERS, SourceWithLayerIDs>

      A record mapping each source name to its MapLibre source ID and an array of the IDs of that source's layers.

      Remarks

      Use these IDs to:

      • Directly manipulate layers using MapLibre's native API
      • Identify which layers on the map belong to this module
      • Set layer ordering or positioning relative to other layers
      • Access source or layer properties through MapLibre methods

      Example

      const ids = myModule.sourceAndLayerIDs;
      console.log(ids);
      // {
      //   mySource: {
      //     sourceID: 'my-source-id',
      //     layerIDs: ['layer-1', 'layer-2']
      //   }
      // }

      // Use with MapLibre API
      const map = myModule.mapLibreMap;
      ids.mySource.layerIDs.forEach(layerId => {
        map.setLayoutProperty(layerId, 'visibility', 'visible');
      });

    getConfig

    • getConfig(): NonNullable<RoutingModuleConfig> | undefined

      Returns a shallow copy of the current module configuration, or undefined if none is applied.

      Returns NonNullable<RoutingModuleConfig> | undefined

      A shallow copy of the current configuration, or undefined. It is a copy so that you can't modify the internal state by accident.

      Remarks

      Only the top-level properties are copied. Nested objects and arrays still reference the original configuration. This is enough for most use cases, but keep it in mind with complex configurations.

      Example

      // Apply a configuration
      myModule.applyConfig({ visible: true, color: '#E63312' });

      // Later, retrieve the current configuration
      const currentConfig = myModule.getConfig();
      console.log(currentConfig); // { visible: true, color: '#E63312' }

      // When no config is applied
      myModule.resetConfig();
      console.log(myModule.getConfig()); // undefined

      See

      • applyConfig to modify the configuration
      • resetConfig to clear the configuration

    selectRoute

    • selectRoute(index: number): Promise<void>

      Changes which route appears as selected.

      Parameters

      • index: number

        Zero-based index of the route to select.

      Returns Promise<void>

      Remarks

      The selected route appears more prominent, thicker and brighter, and the previously selected one takes the deselected style. The sections, guidance and other route features update with it.

      Show the routes with showRoutes first, and pass an index within their range.

      Example

      // Show multiple routes
      await routingModule.showRoutes(routes);

      // User clicks alternative route
      await routingModule.selectRoute(1);

      // Switch back to first route
      await routingModule.selectRoute(0);

    • setEventState(options: SetEventStateOptions): void

      Puts an event state on one of the shown features, as a user interaction would.

      Parameters

      • options: SetEventStateOptions

      Returns void

      Remarks

      The state is what the module's own layers draw (place pins and entry points, route outlines, geometries, details-module incidents, area-analytics cells), what layers of yours read with ['get', 'eventState'], and what getEventStates returns. It lasts as long as the shown feature does, through setVisible, style and configuration changes, but not a new show, a clear or a setStyle with resetState.

      module.setEventState({ index: 2, state: 'hover', mode: 'add' });

    showRoutes

    • showRoutes(routes: Route | Routes, options?: ShowRoutesOptions): Promise<void>

      Displays the given routes on the map.

      Parameters

      • routes: Route | Routes

        Route data from Routing API or custom routes.

      • Optionaloptions: ShowRoutesOptions

        Optional configuration for route selection and display.

        • selectedIndex

          Index of the route to display as selected (default: 0).

      Returns Promise<void>

      Remarks

      This method doesn't show waypoints. It draws route lines, not start, stop or destination markers. To show them, call showWaypoints separately.

      This method:

      • Replaces any previously shown routes
      • Shows all route-related features: lines, sections, guidance and summary bubbles
      • Selects the first route by default, which then appears more prominent

      It draws:

      • Main route lines (selected and deselected styles)
      • Traffic sections with delays
      • Ferry, tunnel, charged-road (tollRoad) and vehicle-restricted sections, speed-limit signs, and the other section types sections shows
      • Turn-by-turn instruction lines and arrows
      • Country-crossing markers and summary bubbles with distance/time/traffic info, unless turned off

      Example

      Show a route (no waypoint markers):

      await routing.showRoutes(routes);
      // Waypoint markers are NOT shown — call showWaypoints() to add them

      Example

      Show routes and waypoint markers:

      const locations = [[4.9, 52.4], [4.5, 51.9]];
      const routes = await calculateRoute({ locations });
      await routing.showRoutes(routes);
      await routing.showWaypoints(locations); // Show start/destination markers separately

      Example

      Show multiple routes with specific selection:

      await routing.showRoutes(routes, { selectedIndex: 1 });

    showWaypoints

    • showWaypoints(waypoints: PlanningWaypoint[] | Waypoints): Promise<void>

      Displays waypoint markers (start, stop, and destination pins) on the map.

      Parameters

      • waypoints: PlanningWaypoint[] | Waypoints

        An array of planning waypoints or a Waypoints FeatureCollection.

      Returns Promise<void>

      Remarks

      showRoutes doesn't show waypoint markers, so call this method separately.

      Pass every location the route is calculated through, so that its pin carries its role and stop mark and the route's events reach it. Show a place the user is still choosing among as a PlacesModule marker instead, and clear it there once it joins the route. Each pin draws as RoutingModuleConfig.waypoints sets, including the per-role pins and an icon mapped from the waypoint's data.

      Example

      Show routes and then waypoints:

      const locations = [[4.9041, 52.3676], [4.4777, 51.9244]];
      const routes = await calculateRoute({ locations });
      await routingModule.showRoutes(routes);
      await routingModule.showWaypoints(locations); // Must be called separately

    updateConfig

    • updateConfig(partial: Partial<NonNullable<CFG>>): void

      Changes part of the configuration and keeps the rest.

      The given properties are laid over the current configuration one level deep, so a nested object you pass replaces the one that was there. The result is applied with applyConfig. This works the same on every module, whatever its applyConfig does with a whole configuration.

      Returns void

      Example

      Waits until the map is ready, then creates an instance of the module.

      Remarks

      RoutingModule owns the sources, layers and images it adds, all suffixed per instance. So every call returns a new, independent instance, and you can stack several of them on one map.

          entryPoints: 'main-when-available'
        }
      });

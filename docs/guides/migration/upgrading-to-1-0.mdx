Before 1.0, a minor release can carry a breaking change. A rename takes effect in one release, with no deprecated alias and no runtime warning. Below is every breaking change on the way to 1.0, each as one row from what your code does now to what it does after.

**This guide covers upgrades from 0.51.x to 1.0.0** (0.52.0, 0.53.0, 0.54.0, 0.55.1, 0.56.0, 0.57.0, 0.58.0, 0.59.0, 0.60.0, 0.61.0, 0.62.0, 0.62.2, 0.63.0, 0.64.0 and 1.0.0, not yet released). Breaking changes before 0.52.0 are in the package's `CHANGELOG.md`. The list grows with each pre-1.0 minor until 1.0 ships.

## How to use this guide

- Find your current release, then apply every row with a later **Since** release, in order.
- The compiler finds most rows for you, because a removed or renamed name is a type error. Rows marked **behaviour** compile unchanged but draw or answer differently, so check those by hand.
- Upgrade the plugins with the SDK. Each one declares the first SDK release it needs, listed under [Plugins](#plugins).

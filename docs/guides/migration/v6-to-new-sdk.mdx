Maps SDK for Web V6 was deprecated on February 1, 2025, and its CDN endpoints were withdrawn on February 1, 2026: they answer `404` unless your contract runs past that date, and then only until it ends. The SDK receives no further updates, security patches, or bug fixes.
The new **Maps SDK for JavaScript** is TomTom's strategic investment for web developers — built from the ground up with modern standards and designed to grow with your application.

<Blockquote>
  ⚡ **Migration carries zero additional cost.** Your existing API key, contract, and pricing all remain the same. Every API call is billed identically whether it originates from V6 or the new SDK.
</Blockquote>

---

## Why migrate

| Benefit | What it means for you |
|---|---|
| **Map + services integration** | Service results plug directly into map modules. A route, a place search, or a traffic query renders on the map with production-quality styling in one step — no manual `addSource`/`addLayer` boilerplate. Defaults are polished; every module is customizable when you need more control. |
| **Future-proof foundation** | Built on [MapLibre GL JS](../map/about-maplibre.mdx) (open-source, BSD-licensed). No vendor lock-in on the rendering engine. Active community, frequent releases, growing plugin ecosystem. |
| **Orbis Maps access** | First SDK with native support for TomTom Orbis Maps — the next generation of TomTom's map data platform, combining open and proprietary sources for industry-leading freshness and accuracy. |
| **Smaller bundles** | Modular ESM architecture with full tree-shaking. Import only what you use. Typical production bundles are significantly smaller than V6's monolithic UMD files. |
| **First-class TypeScript** | Complete type definitions ship with the package. IntelliSense, compile-time safety, and self-documenting APIs — no separate `@types` install needed. |
| **Cross-platform ready** | The services bundle runs in the browser, Node.js 24+, and React Native from a single codebase. Build server-side geocoding, routing enrichment, or mobile services without separate packages. |
| **Native GeoJSON** | Places, routes, reachable ranges, geometries and traffic come back as standard [GeoJSON](https://geojson.org/) (the POI category, EV availability and search-suggestion services return plain objects). No conversion steps — pass results directly to the map, to deck.gl, to your database, or to any GeoJSON-compatible tool. |
| **Your brand on the map** | Restyle the map at runtime without a style editor: [semantic knobs](../map/styling.mdx) for label sizes, road widths and traffic colours, [your brand colours](../map/styling-map-colors.mdx) in one call, and a [theme derived](../plugins/map-theme.mdx) from your site's CSS or an image. Routes, areas and pins follow the same accent colour. |
| **Built for AI** | A [coding-agent skill](../ai-coding.mdx) teaches Claude Code, Cursor, Copilot and others the SDK, and the [Agent Toolkit](../plugins/agent-toolkit/overview.mdx) turns the map into something your users can talk to. |
| **Same pricing** | Your API key, contract terms, and per-call pricing are unchanged. Migration is a code change, not a commercial change. |

## Estimating migration effort

Every integration is different. Use the table below to estimate effort based on which V6 features you currently use.

| What you use today | Effort | What to expect |
|---|:---:|---|
| Basic map display only | **Low** | Replace map initialization (`tt.map` → [`TomTomMap`](../map/tomtom-map.mdx)). Update CSS import. Typically under 1 day. |
| Map + markers + popups | **Low** | Markers use [MapLibre's API](../map/about-maplibre.mdx) — nearly identical pattern. Popups are the same concept. Expect a few hours of find-and-replace. |
| Map + routing display | **Low–Medium** | Route calculation returns GeoJSON natively — simpler than V6. |
| Map + traffic layers | **Low–Medium** | Traffic is integrated into the map module. Replace `stylesVisibility` config with the new [traffic module configuration](../map/traffic.mdx). |
| Search / geocoding services | **Low** | Import from `@tomtom-org/maps-sdk/services` instead of `tt.services`. Fuzzy, category, nearby, geometry and along-route search become one [`discoverPlaces`](../services/places/search.mdx) function; see the [service mapping](#v6-api-to-new-sdk) below. Typed responses. Server-side Node.js code works with minimal changes. |
| EV routing / charging | **Low** | EV routing has dedicated examples with custom charging stops. [`getPlacesWithEVAvailability`](../services/places/ev-charging-stations-availability.mdx) attaches live availability to the stations a search returns, and the places module draws it under each pin. |
| Custom map styles (Map Styler) | **Low–Medium** | Rebuild the look in [Map Maker](../map/styles.mdx#styles-from-map-maker), or start from a standard style and restyle it in code with [styling knobs](../map/styling.mdx) and [`setMapColors`](../map/styling-map-colors.mdx). |
| SearchBox plugin | **Medium** | No drop-in SearchBox plugin yet. Build on [`getSearchSuggestions()`](../services/places/suggest.mdx), with the [search playground](../../examples/search-playground) as a starting point, or use a [MapLibre geocoder plugin](../map/about-maplibre.mdx). |
| Minimap / DrawingTools plugins | **Medium** | No first-party equivalents yet. Use [MapLibre community plugins](../map/about-maplibre.mdx). |
| Custom data visualization | **Low** | Your layer specs carry over unchanged: through MapLibre's `addSource`/`addLayer` as before, or the [Custom GeoJSON module](../map/custom.mdx), which keeps them across style switches and adds SDK events. GeoJSON heatmaps, clusters, and choropleth maps work out of the box. |
| CDN-only deployment (no bundler) | **Medium** | The new SDK requires npm and a bundler (Vite, Webpack). If your project has no build step, you will need to introduce one. This is a one-time setup cost. |

<Blockquote>
  💡 For most integrations using map display + routing + traffic, expect **2–4 developer-days** of migration work. The API patterns are intentionally similar, and the 110+ runnable examples make it easy to validate each feature.
</Blockquote>

## V6 API to new SDK

Find each V6 call you use, and its replacement. Services come from `@tomtom-org/maps-sdk/services` and map classes from `@tomtom-org/maps-sdk/map`; none takes a `key`, which the [global configuration](../core/global-config.mdx) holds instead.

### Map

| V6 | New SDK |
|---|---|
| `tt.map({ key, container, center, zoom })` | `new TomTomMap({ mapLibre: { container, center, zoom } })` ([TomTom map](../map/tomtom-map.mdx)) |
| `map.setStyle(style)` | `await map.setStyle('standardDark')`: modules keep their data and settings ([Map styles](../map/styles.mdx#dynamic-style-switching)) |
| `stylesVisibility`, `showTrafficFlow()`, `hideTrafficFlow()` | `(await TrafficFlowModule.get(map)).setVisible(true)` ([Traffic flow](../map/traffic-flow.mdx)) |
| `showTrafficIncidents()`, `hideTrafficIncidents()` | `(await TrafficIncidentsModule.get(map)).setVisible(true)` ([Traffic incidents](../map/traffic-incidents.mdx)) |
| `showPOI()`, `hidePOI()` | `(await POIsModule.get(map)).setVisible(false)` ([POIs](../map/pois.mdx)) |
| `map.setLanguage(language)` | `map.setLanguage(language)`, or `language` in the global configuration for the map and services |
| `map.setGeopoliticalView(view)`, tiles only | `map.setGeopoliticalView(view)`, or `geopoliticalView` in the global configuration for the map and services ([Geopolitical views](../core/geopolitical-views.mdx)) |
| `tt.Marker`, `tt.Popup` | `Marker`, `Popup` from `maplibre-gl`, or the [Places module](../map/places.mdx) for many pins |
| `map.addLayer(…)` with a route's `toGeoJson()` | `(await RoutingModule.create(map)).showRoutes(routes)` ([Routes](../map/routes.mdx)) |
| `map.addLayer(…)` with your own GeoJSON | the [Geometries](../map/geometries.mdx) or [Custom GeoJSON](../map/custom.mdx) module, or `map.mapLibreMap.addLayer(…)` |

## Step-by-step migration

You can migrate incrementally. Tackle only the sections relevant to your integration.

The new SDK operates at two levels — and you can mix them freely.

- At the **high level**, map modules and services are tightly integrated: a route calculation, a place search, or a traffic query can flow directly into the map with production-quality visualization in just a few lines — no manual layer management, no custom styling boilerplate.
- At the **low level**, the underlying [MapLibre GL JS](../map/about-maplibre.mdx) instance is always accessible via `map.mapLibreMap`, giving you MapLibre's full raw API. That escape hatch is also the most direct migration path for V6 code that called the map's low-level methods; move each feature up to a module as you go, for [what the SDK adds](../map/about-maplibre.mdx#what-the-sdk-adds-over-raw-maplibre).

### Install the new SDK

Remove the legacy packages and CDN references. Install the new SDK:

```bash
# Remove legacy packages
npm uninstall @tomtom-international/web-sdk-maps @tomtom-international/web-sdk-services

# Install new SDK (peer dependencies installed automatically)
npm install @tomtom-org/maps-sdk
```

Also remove any V6 CDN `<script>` and `<link>` tags from your HTML.

<Blockquote>
  🔑 Your existing TomTom API key works with the new SDK. No new key or contract change is needed.
</Blockquote>

### Set up centralized configuration

The new SDK uses a [singleton configuration pattern](../core/quickstart.mdx). Set your API key once at application startup and it applies to all maps and service calls automatically.

**Before (V6):**
```javascript
// API key passed to every call individually
var map = tt.map({ key: 'YOUR_API_KEY', container: 'map' });
tt.services.fuzzySearch({ key: 'YOUR_API_KEY', query: 'pizza' });
```

**After:**
```typescript
import { TomTomConfig } from '@tomtom-org/maps-sdk/core';

// Set once at app startup — used by all maps and service calls
TomTomConfig.instance.put({
    apiKey: 'YOUR_API_KEY',
    language: 'en-GB',
});
```

You can still override the key per-call or per-map instance when needed.

### Migrate map initialization

**Before (V6):**
```javascript
var map = tt.map({
    key: 'YOUR_API_KEY',
    container: 'map',
    center: [4.8156, 52.4414],
    zoom: 8,
});
```

**After:**
```typescript
import { TomTomMap } from '@tomtom-org/maps-sdk/map';

const map = new TomTomMap({
    mapLibre: {
        container: 'map',
        center: [4.8156, 52.4414],
        zoom: 8,
    },
});
```

Map options (`center`, `zoom`, `bearing`, `pitch`, and all other [MapLibre options](../map/about-maplibre.mdx)) are passed through unchanged under the `mapLibre` key.

**Available [styles](../map/styles.mdx):**

| V6 style name | New SDK style ID |
|---|---|
| `basic_main` / `basic_night`, `2/basic_street-light` / `2/basic_street-dark` | `standardLight` / `standardDark` |
| `driving_main` / `driving_night` | `drivingLight` / `drivingDark` |
| `hybrid_main`, or `labels_main` over your own imagery | `satellite`, which carries imagery, roads and labels in one style |
| — | `monoLight` / `monoDark`, muted backdrops for your own data |

V6's separate `trafficFlow`, `trafficIncidents` and `poi` styles have no names of their own: the traffic parts are loaded with `include` (see [Migrate traffic layers](#migrate-traffic-layers)), and the style's own POIs are shown, hidden and filtered with the [POIs module](../map/pois.mdx).

```typescript
const map = new TomTomMap({
    style: 'standardDark',
    mapLibre: { container: 'map' },
});
```

Switching style at runtime is `await map.setStyle('standardLight')`. Unlike V6, where `setStyle` dropped every layer you had added, the SDK's modules keep their data and settings and redraw on the new style ([Map styles](../map/styles.mdx#dynamic-style-switching)).

### Migrate routing

**Before (V6):**
```javascript doc-resolution-skip
tt.services.calculateRoute({
    key: 'YOUR_API_KEY',
    locations: '4.89,52.37:4.88,52.36',
}).then(function(routeData) {
    var geojson = routeData.toGeoJson();
    map.addLayer({ /* ... */ });
});
```

**After:**
```typescript
import { calculateRoute } from '@tomtom-org/maps-sdk/services';
import { RoutingModule } from '@tomtom-org/maps-sdk/map';

const routes = await calculateRoute({
    locations: [
        [4.89, 52.37],   // [longitude, latitude]
        [4.88, 52.36],
    ],
    travelMode: 'car',
});

// Pass directly to RoutingModule — no .toGeoJson() or manual layer setup needed
const routingModule = await RoutingModule.create(map);
await routingModule.showRoutes(routes);
```

The response is standard GeoJSON. No `.toGeoJson()` conversion step. [`RoutingModule`](../map/routes.mdx) handles all layer management, default styling, waypoint icons, and traffic-section coloring automatically — the route renders on the map with a single call and looks production-ready by default. If you need a different color scheme, custom line widths, or your own waypoint markers, the module exposes configuration options for each.

If you prefer to manage the map layers yourself (closer to how V6 worked), the GeoJSON response passes directly to `map.mapLibreMap.addSource` / `addLayer`:

```typescript
// Low-level approach — use the MapLibre instance directly
map.mapLibreMap.addSource('route', { type: 'geojson', data: routes });
map.mapLibreMap.addLayer({ id: 'route-line', type: 'line', source: 'route', paint: { 'line-color': '#0080ff', 'line-width': 4 } });
```

Layers added this way are dropped by `setStyle` and get no SDK events. To keep your own layer specs with both, give them to the [Custom GeoJSON module](../map/custom.mdx) instead.

### Migrate search and geocoding

Search and geocoding responses are standard GeoJSON — you can pass them directly to the map. For a fully integrated experience, [`PlacesModule`](../map/places.mdx) renders search results on the map as styled, interactive markers with minimal setup. For a lean, data-only integration, the GeoJSON features work equally well with any MapLibre data source.

**Before (V6):**
```javascript
tt.services.fuzzySearch({
    key: 'YOUR_API_KEY',
    query: 'restaurant',
    center: { lat: 52.37, lng: 4.89 },
}).then(function(results) { /* ... */ });
```

**After:**
```typescript
import { discoverPlaces } from '@tomtom-org/maps-sdk/services';

const results = await discoverPlaces({
    query: 'restaurant',
    geoBias: { position: [4.89, 52.37] }, // [longitude, latitude]
});
// results is a typed GeoJSON FeatureCollection — access via results.features
```

For reverse geocoding:

**Before (V6):**
```javascript
tt.services.reverseGeocode({
    key: 'YOUR_API_KEY',
    position: { lat: 52.37, lng: 4.89 },
}).then(response => { /* ... */ });
```

**After:**
```typescript
import { reverseGeocode } from '@tomtom-org/maps-sdk/services';

const place = await reverseGeocode({ position: [4.89, 52.37] });
const address = place.properties.address;
```

### Migrate traffic layers

Traffic is one of the areas where the tight map + services integration pays off most visibly. `TrafficFlowModule` and `TrafficIncidentsModule` connect the live TomTom traffic data to the map with pre-styled, interactive layers. Incident markers are clickable and richly styled out of the box; you can filter by magnitude, category, or road type without writing any rendering logic. The modules are also directly customizable if you need a different visual treatment.

**Before (V6):**
```javascript
var map = tt.map({
    key: 'YOUR_API_KEY',
    container: 'map',
    stylesVisibility: { trafficFlow: true, trafficIncidents: true },
});
// Toggle later:
map.showTrafficFlow();
map.hideTrafficFlow();
```

**After:**
```typescript
import { TomTomMap, TrafficFlowModule, TrafficIncidentsModule } from '@tomtom-org/maps-sdk/map';

// Include traffic layers when initializing the map style
const map = new TomTomMap({
    style: { type: 'standard', id: 'standardLight', include: ['trafficFlow', 'trafficIncidents'] },
    mapLibre: { container: 'map' },
});

const trafficFlow = await TrafficFlowModule.get(map, { visible: true });
const trafficIncidents = await TrafficIncidentsModule.get(map, { visible: true });

// Toggle visibility
trafficFlow.setVisible(false);
trafficIncidents.setVisible(true);

// Typed filtering — show only major and moderate incidents
trafficIncidents.updateConfig({
    filters: {
        any: [{
            magnitudes: { show: 'only', values: ['major', 'moderate'] },
        }],
    },
});
```

### Migrate custom styling

In V6, restyling the map meant editing a style in Map Styler and loading its JSON. Map Maker remains the tool for a [style of your own](../map/styles.mdx#styles-from-map-maker), but most brand adjustments need none: the [Styling module](../map/styling.mdx) changes a standard style at runtime, and the change survives style switches.

```typescript
import { StylingModule } from '@tomtom-org/maps-sdk/map';

const styling = await StylingModule.get(map);
styling.set('labels.sizeFactor', 1.2);      // every base-map label 20% bigger
styling.set('buildings.3d', true);          // extruded buildings
styling.setMapColors({ land: '#f3f5f7', water: '#accbe2', roadMajor: '#a1b8ce' });
```

The [map theme plugin](../plugins/map-theme.mdx) derives those colours for you from your brand colours, your site's CSS or an image, and [`exportStyle`](../map/styling.mdx#exporting-the-style) saves the result as a style file.

### Update CSS

**Before (V6):**
```html
<link rel='stylesheet' href='https://api.tomtom.com/maps-sdk-for-web/cdn/6.x/.../maps.css'>
```

**After:**

The SDK applies the [MapLibre CSS](../map/about-maplibre.mdx#maplibre-css) itself, from its own bundle. You only need this import to use the CSS of the MapLibre version you installed.

```javascript
// In your JS/TS entry point
import 'maplibre-gl/dist/maplibre-gl.css';
```

| Component | V6 (min + gzip) | New SDK |
|---|---|---|
| Maps library | ~720 KB monolithic | ~220 KB MapLibre + SDK modules (tree-shaken) |
| Services library | ~175 KB monolithic | Import only what you use (significantly smaller) |
| Total (maps + routing) | ~895 KB | Substantially reduced |

### Rendering engine

- [MapLibre GL JS](../map/about-maplibre.mdx) is actively maintained with performance improvements in every release
- Vector tile rendering leverages WebGL 2 on supported browsers
- [Style part lazy loading](../map/styles.mdx) enables faster initial map display by loading layers on demand
- [Layer group visibility animation](../../examples/layer-groups-visibility-animation) support for smooth UX transitions

### API response handling

- Native GeoJSON responses eliminate the serialisation/deserialisation overhead of V6's `.toGeoJson()` conversion
- Typed responses enable compile-time validation, reducing runtime errors

### Developer velocity

- 110+ runnable examples with Sandpack — copy, modify, ship
- An [AI coding-agent skill](../ai-coding.mdx) that gives your agent the SDK's patterns and APIs
- Full TypeScript IntelliSense means less time reading docs, more time coding
- Centralised configuration eliminates the "forgot the API key" class of bugs

Migration is a code change, not a commercial event.

## Using TomTom map with MapLibre directly

`TomTomMap` exposes the underlying MapLibre GL JS instance via `map.mapLibreMap`. Once you have that reference, the full MapLibre API is available — `addSource`, `addLayer`, `on`, `queryRenderedFeatures`, and everything else — exactly as it works in a standalone MapLibre project.

This is the **most direct migration path** for V6 code that calls TomTom's `tt.map` methods directly. You can replace `tt.map(...)` with `new TomTomMap(...)`, swap the CSS import, and then address the rest of the codebase incrementally: each time a feature is ready to adopt a high-level module, replace the manual layer code; everything else keeps working unchanged via `map.mapLibreMap`.

```typescript
import { TomTomMap } from '@tomtom-org/maps-sdk/map';

const map = new TomTomMap({ mapLibre: { container: 'map' } });

map.mapLibreMap.on('load', () => {
    // Standard MapLibre API
    map.mapLibreMap.addSource('my-data', { type: 'geojson', data: myGeojson });
    map.mapLibreMap.addLayer({ id: 'my-layer', type: 'fill', source: 'my-data' });
});
```

Custom data visualization — heatmaps, clustering, choropleth maps, deck.gl layers — all work through `map.mapLibreMap` without any SDK-specific code. The high-level modules and the raw MapLibre API coexist on the same map instance, so you can use both at once. For GeoJSON layers, the [Custom GeoJSON module](../map/custom.mdx) takes the same layer specs and restores them after every style switch.

## What's not yet available

The new SDK is in **Public Preview** (0.x versions): until 1.0, a minor release can carry a breaking change, each listed in [Upgrading to 1.0](./upgrading-to-1-0.mdx). Some V6 capabilities are not yet available as first-party SDK features:

- **SearchBox plugin** — no drop-in replacement yet; build on [`getSearchSuggestions()`](../services/places/suggest.mdx), starting from the [search playground](../../examples/search-playground)
- **Minimap / DrawingTools plugins** — use [MapLibre community plugins](../map/about-maplibre.mdx), listed in [awesome-maplibre](https://github.com/maplibre/awesome-maplibre)
- **Turn-by-turn navigation UI** — in-car navigation UI components are not yet available
- **Matrix routing, structured geocoding, cross-street lookup, static map images, traffic flow segment data and incident viewport** — no SDK function yet; call those TomTom APIs over HTTP. For structured geocoding, pass the full address to [`geocode`](../services/places/geocoding.mdx)
- **CDN-only deployment** — the new SDK requires a bundler (Vite, Webpack, etc.)

For GeoJSON data no first-party module covers, use the [Custom GeoJSON module](../map/custom.mdx); for anything else, `map.mapLibreMap` gives you the full MapLibre GL JS API as a fallback — see the section above.

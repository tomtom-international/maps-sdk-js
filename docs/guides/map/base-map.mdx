The Base Map Module shows and hides the layers of the base map — land, water, buildings, roads, borders and their labels — by layer group, and reports the user events on them. The demo below toggles each group:

**What this module owns:** whether each base-map layer group is shown, and the user events on them. How the base map looks — label and road sizes, the ten map colours, 3D buildings, projection and sky — belongs to the [Styling module](./styling.mdx). Its group toggle knobs (`basemap.<group>`, `buildings.*`, `roads.shields`) write through this module, so the later call wins, and the toggles inside a group only hide what this module shows. See [Who owns what](./modules.mdx#who-owns-what).

## Layer groups

The Base Map Module organizes map content into logical layer groups that can be controlled independently. It supports the [following groups](/maps-sdk-js/api-reference/types/map.BaseMapLayerGroupName.html), exported as `baseMapLayerGroupNames`:

`land`, `water`, `natureLabels`, `roads`, `railways`, `ferries`, `buildings2D`, `buildings3D`, `borders`, `roadLabels`, `roadShields`, `houseNumbers`, `allPlaceLabels`, `smallerTownLabels`, `cityLabels`, `capitalLabels`, `stateLabels`, `countryLabels`

### Every setting as data

`baseMapKnobCatalogue` lists every setting of the module's configuration with its kind and a
description. Each id is the setting's path in the config, so a UI can build its controls from it,
with no map loaded:

```javascript
import { baseMapKnobCatalogue } from '@tomtom-org/maps-sdk/map';

const groupToggles = baseMapKnobCatalogue.filter(({ id }) => id.startsWith('groups.'));
// [{ id: 'groups.land.visible', kind: 'toggle', description: 'The `land` layer group: …' }, …]
```

- The ids are `visible`, then `groups.<group>.visible` for each group above, in the order of
  `baseMapLayerGroupNames`.
- No entry carries a default: unset, a layer is drawn as the style ships it, and some groups, such
  as `buildings3D`, ship hidden.
- `baseMapKnobIds` lists the ids in catalogue order, `BaseMapKnobId` is their union, and
  `BaseMapKnobValueOf<ID>` the plain value one takes.
- The [styling toggle](./styling.mdx#the-knob-catalogue) on the same group is `basemap.<group>`, or
  the one named in *What this module owns* above, and a `basemap.<group>` entry describes its group
  in the same words. Both catalogues' entries share one shape, `KnobEntry`.

## Basic setup

First set up your project and map following the [Map quickstart guide](../map/quickstart.mdx) and ensure you have a running [TomTomMap](/maps-sdk-js/api-reference/classes/map.TomTomMap.html) instance.

### Standard base map initialization

For comprehensive base map functionality, initialize the module with default settings:

```javascript
import { BaseMapModule } from '@tomtom-org/maps-sdk/map';

const baseMap = await BaseMapModule.get(map);
```

### Initializing with a layer group hidden

`groups` sets the initial state of each layer group, and can be changed later with [setVisible()](/maps-sdk-js/api-reference/classes/map.BaseMapModule.html#setvisible):

```javascript
const baseMap = await BaseMapModule.get(map, {
    groups: { buildings2D: { visible: false }, buildings3D: { visible: false } }
});
```

`visible` applies to every layer first, then each entry of `groups` in the order given, so a later entry wins where two groups share layers (`allPlaceLabels` and `cityLabels`). Whatever neither sets is drawn as the style ships it — and so is a group whose entry leaves `visible` out, which is how to keep a few groups exactly as the style draws them:

```javascript
// Only land, water and roads, each as the style ships it
await BaseMapModule.get(map, { visible: false, groups: { land: {}, water: {}, roads: {} } });
```

Showing a group shows every layer in it, including the ones the style ships hidden, such as detailed road markings.

### Layer group modes

Every map has one base map module — a second `BaseMapModule.get(map)` returns the same instance. You
name the layer groups you care about per call instead: `setVisible` / `isVisible` for visibility, and
[`events.where({ layerGroups })`](./user-events.mdx#scoping-events) for events, which takes its own
cursor configuration.

Both take a `mode`:

- **Include Mode**: acts only on the layers in `names`
- **Exclude Mode**: acts on every layer *except* those in `names`, which `setVisible` leaves as they were

```javascript
// Show only land, water and borders
baseMap.setVisible(false);
baseMap.setVisible(true, { layerGroups: { mode: 'include', names: ['land', 'water', 'borders'] } });

// Hide the buildings layers, leaving the rest as it is
baseMap.setVisible(false, { layerGroups: { mode: 'include', names: ['buildings2D', 'buildings3D'] } });

// Show everything except the labels
baseMap.setVisible(true, {
    layerGroups: { mode: 'exclude', names: ['allPlaceLabels', 'roadLabels', 'cityLabels'] }
});
```

## Dynamic control

### Changing visibility

Control base map visibility dynamically based on application state:

```javascript
// Toggle overall base map visibility
baseMap.setVisible(false);

// Read the setting back
if (!baseMap.isVisible()) {
    console.log('Base map is hidden');
}
```

`isVisible()` reads the settings rather than the layers: `visible`, then the `groups` and the
styling toggles over them, the later winning. A layer none of them reaches reports what the style
draws.

`setVisible` and `isVisible` both accept the layer groups to act on, so one module backs a control per group — no second module needed:

```javascript
const layerGroups = { mode: 'include', names: ['buildings3D'] };

// Until a call sets the group, this is what the style ships (buildings3D usually starts hidden)
checkbox.checked = baseMap.isVisible({ layerGroups });

checkbox.addEventListener('change', () => baseMap.setVisible(checkbox.checked, { layerGroups }));
```

Every `setVisible` call is kept in `getConfig().groups` (a call without groups replaces the record with `visible`), so a `setStyle` restores all of them, in order. A call over a group also takes it over from its styling toggle knob, which it removes from `styling.getConfig()`.

### Applying configuration updates

`applyConfig` replaces the whole configuration: what the new one leaves out goes back to how the style ships it. `updateConfig` merges into the current configuration, key by key.

```javascript
// Hides the house numbers; every other group goes back to the style
baseMap.applyConfig({ groups: { houseNumbers: { visible: false } } });

// Also hides the ferries, keeping the house numbers hidden
baseMap.updateConfig({ groups: { ...baseMap.getConfig()?.groups, ferries: { visible: false } } });
```

## Event handling

The Base Map Module provides [event handling](/maps-sdk-js/api-reference/classes/map.BaseMapModule.html#events) capabilities for interactive applications:

```javascript
const baseMap = await BaseMapModule.get(map);

// Handle clicks on base map features
baseMap.events.on('click', (feature, lngLat) => {
    console.log('Base map feature clicked:', feature.properties);

    if (feature.properties.building) {
        showBuildingDetails(feature.properties);
    } else if (feature.properties.road_name) {
        showRoadInformation(feature.properties);
    }
});

// Handle hover for feature identification
baseMap.events.on('hover', (feature, lngLat) => {
    showFeaturePreview(feature.properties, lngLat);
});
```

## Combining with other modules

The base map, the POIs and the traffic layers are separate modules over one style, so a focused view sets each of them:

```javascript
import { BaseMapModule, POIsModule, TrafficIncidentsModule } from '@tomtom-org/maps-sdk/map';

const baseMap = await BaseMapModule.get(map);
const poisModule = await POIsModule.get(map);
const trafficIncidentsModule = await TrafficIncidentsModule.get(map);

// A navigation view: roads and their labels, live incidents, no POIs
const showNavigationView = () => {
    baseMap.setVisible(false);
    baseMap.setVisible(true, {
        layerGroups: { mode: 'include', names: ['land', 'water', 'roads', 'roadLabels', 'roadShields'] }
    });
    trafficIncidentsModule.setVisible(true);
    poisModule.setVisible(false);
};
```

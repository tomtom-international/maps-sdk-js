`ReachableRangesModule` draws the areas reachable from one or more origins within a budget of time or distance,
as [`calculateReachableRanges`](../services/routing/reachable-ranges.mdx) returns them. Each range is one band,
titled from its budget, nested around its own origin and coloured from the map. Calculating the ranges needs
an API key with Calculate Reachable Range access, which is in private preview. The module draws them on any map.

- It owns the bands, their borders and the labels along them, and how they look: the fill style, palette, labels
  and highlight below.
- It never restyles the base map, which belongs to the [Styling Foundations module](./styling.mdx), and styling
  knobs never reach its layers. Bands with no `palette` read the map's
  [accent and land colours](#band-colours). [Who owns what](./modules.mdx#who-owns-what) draws the line for every
  module.

## Showing ranges

```typescript
import { TomTomConfig } from '@tomtom-org/maps-sdk/core';
import { ReachableRangesModule, TomTomMap } from '@tomtom-org/maps-sdk/map';
import { calculateReachableRanges } from '@tomtom-org/maps-sdk/services';

TomTomConfig.instance.put({ apiKey: 'YOUR_API_KEY' });
const origin: [number, number] = [4.9041, 52.3676];
const map = new TomTomMap({ mapLibre: { container: 'map', center: origin, zoom: 9 } });
const rangesModule = await ReachableRangesModule.create(map);

await rangesModule.show(
    await calculateReachableRanges([10, 20, 30].map((value) => ({ origin, budget: { type: 'timeMinutes', value } }))),
);
```

`show` replaces the ranges shown, and `clear` removes them. The module draws what `calculateReachableRanges`
returns unchanged:

- Ranges are grouped by their `origin`, so one `show` and one request can hold the bands of several places, each
  nested around its own.
- Ranges can come in any order. A smaller range always draws over the larger ones around it.
- Each band's border is labelled from its budget, as [Titles](#titles) describes.

```typescript
const origins: [number, number][] = [[4.9003, 52.3791], [5.1109, 52.0894]];
await rangesModule.show(
    await calculateReachableRanges(
        origins.flatMap((origin) => [10, 20, 30].map((value) => ({ origin, budget: { type: 'timeMinutes', value } }))),
    ),
);
```

## Titles

A range's title is the text of the labels along its border. By default, it is the range's `budget` with its unit,
such as `10 min` or `5 km`, otherwise its position in what `show` was given, from 1. A
`lineLabel.title` function of your own replaces it, and changing it relabels the bands shown:

```typescript
rangesModule.updateConfig({ lineLabel: { title: (feature, index) => `Zone ${index + 1}` } });
```

- `lineLabel` also takes the styling fields every module's labels share: `size`, `color`, `haloColor`, `haloWidth`,
  `opacity` and `font`.
- Unset colours follow the map style: dark text on a white halo on light styles, the reverse on dark ones.
- `updateConfig` replaces the whole `lineLabel`, so spread the current one to keep a title, or set one field with
  `setKnob`:

```typescript
rangesModule.updateConfig({ lineLabel: { ...rangesModule.getConfig()?.lineLabel, size: 13, color: '#1d3f8a' } });
```

## Fill styles

| `fill.style` | Draws |
|---|---|
| `'filled'` (default) | each band coloured, the innermost on top |
| `'outline'` | only each range's border, thick and coloured |
| `'inverted'` | what lies **out** of reach: the world beyond the largest range of every origin, then a ring outside each smaller one |

```typescript
const outOfReach = await ReachableRangesModule.create(map, { fill: { style: 'inverted' } });
```

These are the [geometries module's fill styles](./geometries.mdx#fill-styles), applied per band.

## Band colours

By default, the bands ramp from the map's
[accent](./styling-map-colors.mdx#the-accent-what-a-theme-reaches-beyond-the-base-map) on the innermost band
toward its land colour on the outermost, both read from `map.mapColors`.

- `'inverted'` ramps the other way, deepening away from the origin.
- On a map with no theme, the ramp follows the style's light or dark side: navy `#0A3653` toward white on
  light styles, sky blue `#5FA8D8` toward `#333333` on dark ones. It repaints when you switch.
- If you theme the map, for example with the [map-theme plugin](../plugins/map-theme.mdx), the bands repaint with
  it:

```typescript
import { StylingFoundationsModule } from '@tomtom-org/maps-sdk/map';
import { deriveMapColors } from '@tomtom-org/maps-sdk-plugin-map-theme';

const styling = await StylingFoundationsModule.get(map);
styling.setMapColors(deriveMapColors(['#1d3f8a', '#e63312', '#f5d000', '#f4f1ea'])); // the bands follow
```

`fill.palette` sets colours of your own instead, innermost band first, and starts over after the last. Map
colour changes don't touch them, and an empty list hands the colours back to the map. `updateConfig` replaces
the whole `fill`, so spread the current one to keep its `style`:

```typescript
rangesModule.applyConfig({ fill: { palette: ['#b3001b', '#e85d04', '#faa307'] } });
rangesModule.updateConfig({ fill: { ...rangesModule.getConfig()?.fill, palette: [] } });
```

Bands are ranked per origin, so with several origins the ranges of the same rank share a colour.

## Hovered and clicked bands

Once a handler covers the bands, the band under the pointer draws a denser fill and a wider border in its own
colour. So does a clicked band. The module's
[event state methods](./user-events.mdx#event-states) set that state from your own UI.

- `highlight` sets how much. By default, the fill opacity doubles, up to fully opaque, and the border width
  grows 1.75 times.
- A factor of `1` draws a hovered band like any other.

```typescript
rangesModule.updateConfig({ highlight: { fill: { opacityFactor: 1 }, line: { widthFactor: 2.5 } } }); // a bolder border alone
```

## Events

`events` covers the bands and their labels. A handler receives the band as drawn, with the `title` and `color`
the module gave it in its `properties`:

```typescript
rangesModule.events.on('click', (band) => console.log(band.properties.title)); // '20 min'
```

Two named scopes each cover one surface, with the same handlers and [event states](./user-events.mdx#event-states).
`events.geometry` covers the bands, their borders and the labels along them, which are drawn from the same
features. `events.geometryLabel` covers the title points `getShown()` lists under `geometryLabel`.

```typescript
rangesModule.events.geometry.on('hover', (band) => showTooltip(band.properties.title));
```

The [user events guide](./user-events.mdx) covers the event types and their timings.

## Showing and hiding

`setVisible` hides and shows the bands, borders and labels together, and `visible: false` at creation starts the
module hidden. `show()` and `clear()` never change it, so ranges shown while hidden appear on `setVisible(true)`.
The state survives a style change.

```typescript
rangesModule.setVisible(!rangesModule.isVisible());
```

## Layer position

The bands sit below the map's labels unless `beforeLayerConfig` says otherwise. A single target places the fill
and the borders together, and the record form `{ all?, fill?, line? }` places them separately, as on the
[geometries module](./geometries.mdx#layer-positioning-and-styling):

```typescript
const ranges = await ReachableRangesModule.create(map, {
    beforeLayerConfig: { fill: 'lowestRoadLine', line: 'lowestLabel' }, // fill under the roads
});
```

## Layer overrides

For anything the settings don't cover, `layers` takes a partial MapLibre layer for the bands (`fill`), their
borders (`line`) and labels (`label`, `lineLabel`), the same entries as
[the geometries module's](./geometries.mdx#custom-styling-configuration). `paint` and `layout` merge per property
onto the module's own, in every fill style:

```typescript
ranges.updateConfig({ layers: { line: { paint: { 'line-dasharray': [2, 1] } } } });
```

## Restyling and saving the settings

A config change restyles the bands already shown, without calculating the ranges again. `updateConfig` changes
only what you give it, `applyConfig` replaces the whole config, and `resetConfig` returns to the defaults.

`getConfig()` returns the settings to store. All of it survives JSON except the function `lineLabel.title`.
`ReachableRangesModuleSerializableConfig` types what you parse back, and on replay you add `lineLabel.title` in code:

```typescript
import type { ReachableRangesModuleSerializableConfig } from '@tomtom-org/maps-sdk/map';

localStorage.setItem('ranges', JSON.stringify(rangesModule.getConfig()));

const saved: ReachableRangesModuleSerializableConfig = JSON.parse(localStorage.getItem('ranges') ?? '{}');
rangesModule.applyConfig({ ...saved, lineLabel: { ...saved.lineLabel, title: (feature, index) => `Zone ${index + 1}` } });
```

## Every setting as data

`reachableRangesKnobCatalogue` lists every plain-valued setting of the module with its kind, its range or options
and, where one value holds everywhere, its default. Each id is the setting's path in the config, so a panel can
build its controls from it and set each with `setKnob`:

```typescript
import { reachableRangesKnobCatalogue, setKnob } from '@tomtom-org/maps-sdk/map';

setKnob(rangesModule, reachableRangesKnobCatalogue, 'lineLabel.size', 13);
```

| Id | Kind |
|---|---|
| `visible`, `fill.style`, `fill.palette` | toggle, enum, colours |
| `highlight.fill.opacityFactor`, `highlight.line.widthFactor` | factor, 1 to 4 and 1 to 3 |
| `lineLabel.size`, `lineLabel.color`, `lineLabel.haloColor`, `lineLabel.haloWidth`, `lineLabel.opacity`, `lineLabel.font` | number, colour, colour, number, number, enums |

- The label knobs default like the geometries module's border labels: size 15, halo width 2, opacity 1
  and the font `['Noto-Bold']`.
- `reachableRangesKnobIds` lists the ids in catalogue order, `ReachableRangesKnobId` is their union, and
  `ReachableRangesKnobValueOf<ID>` is the plain value one takes.
- The catalogue leaves out `events`, and `beforeLayerConfig`, `layers` and the labels' `title`, which take
  structured, MapLibre or function values.
- Its entries share their shape, `KnobEntry`, with every [module's catalogue](./modules.mdx#every-setting-as-data).

## Reading shown data

`getShown()` returns what the module draws, as prepared for display:

- `geometry` - The bands with their titles and colours. With `fill.style: 'inverted'`, it holds the shaded rings
  and a copy of each range for its border.
- `geometryLabel` - A title point derived from each band. The labels along the borders are drawn from
  `geometry` itself.

```typescript
const { geometry } = rangesModule.getShown();
console.log(`Bands: ${geometry.features.length}`);
```

## Multiple module instances

The module is data-owned, so each instance has its own sources and layers. Two can show two sets of
ranges side by side, apart from any `GeometriesModule` on the same map.

```typescript
const byCar = await ReachableRangesModule.create(map);
const byBike = await ReachableRangesModule.create(map, { fill: { style: 'outline' } });
```

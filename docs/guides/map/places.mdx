The Places Module allows you to display and interact with [places](../core/places.mdx) on your TomTom map. You can add search results, custom locations, and handle user interactions.

**What this module owns:** the place markers and labels it draws, and how they look — the theme, icon and text configuration below. It never restyles the base map underneath, which belongs to the [Styling module](./styling.mdx), and styling knobs never touch these markers: markers given no colour read the map's [accent](./styling.mdx#the-accent-what-a-theme-reaches-beyond-the-base-map) as their default. See [Who owns what](./modules.mdx#who-owns-what).

<GuideDemo demo="search-places-nearby-location" />

## Initialization

```javascript
import { TomTomMap, PlacesModule } from '@tomtom-org/maps-sdk/map';

// Initialize map
const map = new TomTomMap({ mapLibre: { container: 'map' } });

// Initialize Places module with default configuration
const placesModule = await PlacesModule.create(map);
```

## Displaying places

Display one or multiple places on the map:

```javascript
import { discoverPlaces } from '@tomtom-org/maps-sdk/services';

// Show single place
await placesModule.show({
  id: 'custom-place-1',
  type: 'Feature',
  geometry: { type: 'Point', coordinates: [4.9041, 52.3676] },
  properties: {
    type: 'POI',
    address: { freeformAddress: 'Custom Place 1, Amsterdam' },
    poi: { name: 'Custom Place' }
  }
});

// Show multiple places
await placesModule.show([place1, place2, place3]);

const searchResults = await discoverPlaces({
    query: 'restaurants',
    geoBias: { position: [4.9041, 52.3676] }, // Amsterdam
    limit: 10
});

// Show search results
await placesModule.show(searchResults);

// Remove all places from the map:
await placesModule.clear();
```

## Showing and hiding

`setVisible` hides and shows everything the module draws — places, [connections](/maps-sdk-js/api-reference/classes/map.PlacesModule.html#showconnections)
and [entry points](#entry-points) — while keeping its data. `visible: false` at creation starts it hidden.

```javascript
const placesModule = await PlacesModule.create(map, { visible: false });
await placesModule.show(searchResults); // loaded, not drawn

placesModule.setVisible(true);
placesModule.isVisible(); // true
```

- `show()` and `clear()` never change it, and it survives a style change.
- Showing the module leaves hidden the layers its theme does not use, and any layer you hid
  through `layers.*.layout.visibility`, such as `main` in [micro-only rendering](#theme).

## Custom styling

### Theme

Themes control the overall look of place markers. Choose one at initialization or swap
at runtime:

- `pin` (default): traditional teardrop pin markers
- `circle-icon`: circular markers with a centered category icon
- `base-map`: mimics the base map style's POI layer, combining `main`, `selected`, and
  `micro` layers so places blend in with the style's built-in POIs. To render exclusively
  through the lightweight `POI - Micro` layer — ideal for dense results where a full POI
  treatment would be too heavy — hide the `main` layer via
  `layers.main.layout.visibility = 'none'`.
- `pin-clustered`: pins that merge into a cluster with a count badge while zoomed out — see
  [Clusters](#clusters).

```javascript
// Initialize with a specific theme
const placesModule = await PlacesModule.create(map, { theme: 'base-map' });

// Or swap at runtime
placesModule.applyTheme('circle-icon');

// Micro-only rendering: combine `base-map` with a hidden `main` layer
const placesModule = await PlacesModule.create(map, {
    theme: 'base-map',
    layers: { main: { layout: { visibility: 'none' } } },
});
```

### Clusters

Under the `pin-clustered` theme, `cluster` sets how places cluster and how the count badge looks.
`badge` styles the badge of single-category and mixed-category clusters together, and `source`
takes MapLibre's cluster options:

<GuideDemo demo="places-clustering-playground" />

```javascript
const placesModule = await PlacesModule.create(map, {
    theme: 'pin-clustered',
    // The per-place value the cluster aggregates
    extraFeatureProps: {
        connectorCount: (place) =>
            place.properties.chargingPark?.connectors.reduce((total, { count }) => total + count, 0) ?? 0,
    },
    cluster: {
        badge: { color: '#3f9cd9', radius: { single: 13, mixed: 18 } },
        source: {
            clusterRadius: 100, // default 60
            clusterMaxZoom: 14, // default 17
            // Total charging points across each cluster
            clusterProperties: { connectors: ['+', ['get', 'connectorCount']] },
        },
    },
    // An aggregated value lands on the cluster feature's properties
    layers: { clusterCount: { layout: { 'text-field': ['get', 'connectors'] } } },
});
```

- A `layers` override of `clusterBadge`, `clusterCount`, `clusterMixedBadge` or `clusterMixedCount`
  wins over `badge` for the paint and layout properties it names, and keeps the rest.
- Changing `source` with `applyConfig` recreates the places source.
- The `clusterBaseMapIconIDs` key of `clusterProperties` is reserved for the module's own aggregator.

### Text styling

Customize labels for places using text configuration:

```javascript
// Make POI names red and other places blue
const customTextConfig: PlaceTextConfig = {
    color: ['match', ['get', 'type'], 'POI', '#D32F2F', '#1976D2']
};

// Initialize with custom text styling
const placesModule = await PlacesModule.create(map, {
    text: customTextConfig,
});

// Or apply after initialization
placesModule.applyTextConfig(customTextConfig);
```

### Icon styling

Customize place icons and markers. Custom icons work under every theme: when a category
is mapped, features in that category use the provided sprite; otherwise the theme's
default icon (the base-map style's category/group expression or the default pin) still
renders.

```javascript
// Per-category custom images — layered on top of any theme
const customIconConfig: PlaceIconConfig = {
  categoryIcons: [
    { id: 'RESTAURANT', image: '/icons/food.png', pixelRatio: 2 },
    { id: 'HOTEL_OR_MOTEL', image: '/icons/hotel.png', pixelRatio: 2 }
  ]
};

// Initialize with custom icon styling
const placesModule = await PlacesModule.create(map, {
  theme: 'pin',
  icon: customIconConfig
});

// Or apply after initialization
placesModule.applyIconConfig(customIconConfig);
```

Use `offsetX`/`offsetY` (pixels) on a `categoryIcons` entry to shift a custom icon from its
coordinate — useful when the icon's visual tip isn't at its own geometric bottom or center:

```javascript
const customIconConfig: PlaceIconConfig = {
  categoryIcons: [
    { id: 'RESTAURANT', image: '/icons/food.png', pixelRatio: 2, offsetX: 0, offsetY: -10 }
  ]
};
```

`offsetX`/`offsetY` only apply to `categoryIcons` entries that also provide an `image` — an
entry that references an existing sprite icon by `id` alone ignores them. Setting them on
`PlaceIconConfig.default.image` has no effect. `RoutingModule` charging stop icons support the
same two fields; see the [routes guide](./routes.mdx).

### Extra properties

Add custom properties to places for advanced styling or filtering:

```javascript
placesModule.applyExtraFeatureProps({
    category: (place) => place.properties.poi?.categories?.[0],
    rating: (place) => place.properties.poi?.rating || 0,
    isOpen: true
});
```

A callback receives a `Place` and must return a JSON value. When the places you show carry a
narrower shape — EV charging stations with availability, say — name it on the config and the
callbacks are typed for it:

```typescript
const config: PlacesModuleConfig<EVChargingStationWithAvailabilityPlaceProps> = {
    extraFeatureProps: {
        availabilityRatio: (place) => getChargingPointAvailability(place)?.ratio ?? 0,
    },
};
```

## Entry points

Search, geocoding and reverse geocoding fill a place's [entrances](../core/places.mdx#entry-points)
in `properties.entryPoints`. Set `entryPoints` on the module config to draw them: a dot per
entrance, larger for the main one, with a dotted line back to the place.

<GuideDemo demo="place-entry-points-playground" />

```javascript
const placesModule = await PlacesModule.create(map, {
    entryPoints: {
        showFor: 'clicked', // 'all' | 'selected' (hovered or clicked, the default) | 'clicked'
        minZoom: 16,        // default 15
        layers: { line: { layout: { visibility: 'none' } } }, // MapLibre overrides for `point` and `line`
    },
});

// Only places with an event handler reach the hover and click states
placesModule.events.on('click', (feature) => console.log(feature.properties.title));

// `entryPoints: undefined` stops drawing them
placesModule.updateConfig({ entryPoints: { showFor: 'all' } });
```

- `selected` and `clicked` follow the module's [event states](#programmatic-event-states), so
  `putEventState` draws them too.
- Hovering or clicking an entry point keeps its place's entry points drawn when a handler covers
  them: one on `events` or `events.entryPoints`, not on `events.places` alone. Under `selected`, a
  [recently hovered](./user-events.mdx#recently-hovered-features) place counts too, so they stay
  while the pointer crosses to an entrance.
- The dots draw over the pins and the lines under them.
- Under the `pin-clustered` theme they start at the first zoom without clusters:
  `cluster.source.clusterMaxZoom` plus one, 18 by default.

A reverse geocoding result's geometry is the queried point; move it to `properties.originalPosition`,
the matched address, before showing it:

```javascript
const address = await reverseGeocode({ position: clickedPosition });
await placesModule.show({
    ...address,
    geometry: { ...address.geometry, coordinates: address.properties.originalPosition },
});
```

## Events

### User events

Handle user interactions with places:

```javascript
// Click events
placesModule.events.on('click', (feature, lngLat) => {
    console.log('Click coordinates:', lngLat);
    console.log('Place title:', feature.properties.title);
    console.log('Place coordinates:', feature.geometry.coordinates);
});

// Hover events
placesModule.events.on('hover', (feature, lngLat) => {
    console.log('Hovering over:', feature.properties.poi?.name);
});

// Remove event listeners
placesModule.events.off('click', handler);
```

`events` covers every surface the module draws. Three named scopes narrow it: `events.places` for the
pins alone — typed as `Place`, which is what you want in TypeScript — `events.connections` for
the lines and labels drawn by [showConnections](/maps-sdk-js/api-reference/classes/map.PlacesModule.html#showconnections),
and `events.entryPoints` for the [entry points](#entry-points):

```javascript
placesModule.events.places.on('click', (place) => console.log(place.properties.poi?.name));
placesModule.events.connections.on('click', () => console.log('connection line clicked'));
placesModule.events.entryPoints.on('click', (entryPoint) => {
    // A point at the entrance, whether its dot or its line was hit, with its place attached
    console.log(entryPoint.properties.type, entryPoint.properties.place?.properties.title);
    // It is a valid route location
    calculateRoute({ locations: [origin, entryPoint] });
});
```

### Programmatic event states

Manually control visual states of places:

```javascript
// Highlight first place as if clicked
placesModule.putEventState({
    index: 0,
    state: 'click',
    mode: 'put'
});

// Remove event state from specific place
placesModule.cleanEventState({ index: 0 });

// Remove all hover states
placesModule.cleanEventStates({ states: ['hover'] });

// Remove all event states
placesModule.cleanEventStates();
```

## Multiple module instances

You can create multiple independent instances of the Places module, each with its own configuration and data. This is useful for displaying different sets of places with distinct styling or behavior.

```javascript
// Create separate instances for different purposes
const restaurantPlaces = await PlacesModule.create(map, {
    theme: 'pin',
    icon: {
        categoryIcons: [{ id: 'RESTAURANT', image: '/icons/restaurant.png', pixelRatio: 2 }]
    }
});

const hotelPlaces = await PlacesModule.create(map, {
    theme: 'circle-icon',
    icon: {
        categoryIcons: [{ id: 'HOTEL_OR_MOTEL', image: '/icons/hotel.png', pixelRatio: 2 }]
    }
});

// Each instance manages its own places independently
await restaurantPlaces.show(restaurantResults);
await hotelPlaces.show(hotelResults);
```

## Reading shown data

Use `getShown()` to retrieve the places currently displayed on the map. This returns the exact data previously passed to `show()`:

```javascript
const shown = placesModule.getShown();
console.log(`Showing ${shown.places.features.length} places`);
```

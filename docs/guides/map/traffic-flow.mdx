`TrafficFlowModule` controls the style's live traffic-flow layers. They colour every road by its speed relative to free flow, from free-flowing to stationary, and outline closed roads.

The module owns the visibility, filters and look of the style's traffic-flow layers, including the [colour of each flow level and the line width](#appearance). See [Who owns what](./modules.mdx#who-owns-what).

To show live flow over a whole city, call `get` with `visible: true`. Move the `center` to see another city's traffic:

<SDKGuideLiveCodingExample exampleDirectory="traffic-flow" />

- The [Traffic Incidents Module](./traffic-incidents.mdx) shows traffic **events** (accidents, closures, roadworks) across the map.
- The incidents **along a route** are its [`traffic` sections](./routes-sections.mdx).

## Initialization

```javascript
import { TomTomMap, TrafficFlowModule } from '@tomtom-org/maps-sdk/map';

const map = new TomTomMap({ mapLibre: { container: 'map' } });
const trafficFlowModule = await TrafficFlowModule.get(map);
```

- If the style lacks the `trafficFlow` [style part](./styles.mdx#available-style-parts), `get()` adds it and reloads the style.
- It is [style-owned](./modules.mdx#types-of-modules), so every `get()` on one map returns the same instance.

## Visibility

Flow is hidden until you show it. `isVisible()` returns the `visible` setting, `false` by default.

```javascript
const trafficFlowModule = await TrafficFlowModule.get(map, { visible: true });

trafficFlowModule.setVisible(false);
trafficFlowModule.isVisible(); // false
```

## Filtering

Set `filters` at `get()` or later through `updateConfig` to narrow which roads show flow.

- The fields of `filters` form one filter. A road must match every field you set.
- Each entry of the `any` list of `filters` is an alternative. A road matching any of them shows too.
- A values filter takes `show`, `'only'` or `'all-except'` (`filterShowModes`), and `values`. It applies only when both are set.

### Road category

The playground below filters by road category with checkboxes:

<GuideDemo demo="traffic-flow-playground" />

```javascript
// Major roads only
trafficFlowModule.updateConfig({
    filters: { roadCategories: { show: 'only', values: ['motorway', 'motorway_link', 'trunk'] } },
});

// Every road but residential streets
trafficFlowModule.updateConfig({
    filters: { roadSubCategories: { show: 'all-except', values: ['residential'] } },
});
```

| `roadCategories` value | Road |
|---|---|
| `motorway`, `motorway_link` | High-capacity highways with restricted access, and their ramps |
| `trunk`, `trunk_link` | Major inter-city roads |
| `primary`, `primary_link` | Primary through routes |
| `secondary`, `secondary_link` | Secondary through routes |
| `tertiary`, `tertiary_link` | Connecting roads |
| `street` | Local streets, with a subcategory |
| `service` | Service roads, with a subcategory |
| `track` | Unpaved or agricultural tracks |

- `roadSubCategories` takes the `street` subcategories `unclassified`, `residential` and `living_street` (`streetRoadSubCategories`), and the `service` ones `parking`, `driveway` and `alley` (`serviceRoadSubCategories`).
- Only `street` and `service` roads have a subcategory, so a `roadSubCategories` filter set to `'only'` leaves out every other road.
- `roadCategories` lists the categories as data.

### Road closures

```javascript
trafficFlowModule.updateConfig({ filters: { roadClosures: 'only' } });       // closed roads only
trafficFlowModule.updateConfig({ filters: { roadClosures: 'all-except' } }); // every road but them
```

### Multiple filters

```javascript
// Motorways, or a closed road of any category
trafficFlowModule.updateConfig({
    filters: {
        roadCategories: { show: 'only', values: ['motorway'] },
        any: [{ roadClosures: 'only' }],
    },
});
```

### Reset filters

```javascript
trafficFlowModule.updateConfig({ filters: undefined });
```

## Appearance

`colors` recolours each flow level, and `widthFactor` (0.5 to 2) multiplies the width of the flow lines.

- Each restyles the style's own flow layers. By default, the style's value applies.
- A level's outline follows its colour, as the darker rim the style designed.
- The levels are `free`, `slow`, `queueing`, `stationary`, and `closed` for the outline of closed roads.

```javascript
import { setKnob, TrafficFlowModule, trafficFlowKnobCatalogue } from '@tomtom-org/maps-sdk/map';

const trafficFlowModule = await TrafficFlowModule.get(map, {
    visible: true,
    colors: { slow: '#f59e0b', stationary: '#7f1d1d' },
    widthFactor: 1.5,
});
setKnob(trafficFlowModule, trafficFlowKnobCatalogue, 'colors.free', '#16a34a');
```

[`getStyleColor`](./styling.mdx#the-knob-catalogue) and the bloom scope of the [map effects plugin](../plugins/map-effects-bloom.mdx#scoping-bloom-by-colour) read the level colours by their map-wide ids, such as `traffic.flow.colors.slow`, with or without the module.

## Events

`events.on` takes `click`, `hover`, `long-hover` and the other [user events](./user-events.mdx#event-types). The handler receives the segment as a `TrafficFlowModuleFeature`.

```javascript
const unsubscribe = trafficFlowModule.events.on('click', (segment, lngLat) => {
    console.log(segment.properties.relativeSpeed, segment.properties.roadCategory);
});
```

`on` returns the function that removes the handler. `events.off('click')` removes every `click` handler of the module ([Cleanup](./module-events.mdx#cleanup)).

## Querying visible features

`getRenderedFeatures()` returns the flow segments rendered in the current viewport:

```javascript
const { trafficFlow } = trafficFlowModule.getRenderedFeatures();
const closedRoads = trafficFlow.filter((segment) => segment.properties.roadClosure);
const congested = trafficFlow.filter((segment) => segment.properties.relativeSpeed < 0.5);
```

### What the flow data can and cannot tell you

Orbis traffic flow is vector tiles only, with no service for a road, a point or an area, so `getRenderedFeatures()` is your only flow data.

- Tiles carry `relativeSpeed` (0 to 1, current speed relative to free flow), `roadCategory`, `roadSubcategory` (on `street` and `service` roads), `roadClosure`, `leftHandTraffic` and `displayClass`.
- `absoluteSpeed`, `partOfTwoWayRoad` and `openlr` are always empty. The standard styles don't request the `absolute_speed`, `part_of_two_way_road` or `openlr` tile tags.
- No Orbis flow tile has free-flow speed, travel time, delay in seconds or confidence.
- Results cover the current viewport and zoom. A segment crossing a tile boundary appears once per tile.

For historical speed and congestion aggregated over an area, use the [Traffic Area Analytics](../services/traffic/traffic-area-analytics.mdx) service.

## Every setting as data

`trafficFlowKnobCatalogue` lists the module's plain-valued settings with their kind, options and any default that holds. It is readable with no map loaded:

```javascript
import { trafficFlowKnobCatalogue } from '@tomtom-org/maps-sdk/map';

// [{ id: 'visible', kind: 'toggle', description: '…', default: false },
//  { id: 'filters.roadCategories.show', kind: 'enum', description: '…', options: ['only', 'all-except'] },
//  { id: 'filters.roadCategories.values', kind: 'enums', description: '…', options: ['motorway', …, 'track'] }, …]
```

| Id | Kind |
|---|---|
| `visible` | toggle, `false` by default |
| `filters.roadCategories.show`, `filters.roadSubCategories.show`, `filters.roadClosures` | enum: `only` or `all-except` |
| `filters.roadCategories.values` | enums: the [road categories](#road-category) |
| `filters.roadSubCategories.values` | enums: the street, then the service road subcategories |
| `colors.free`, `colors.slow`, `colors.queueing`, `colors.stationary`, `colors.closed` | colour, the style's own by default |
| `widthFactor` | factor 0.5–2, `1` by default |

- The `filters` knobs set the fields of the [filter](#filtering). The `any` list of `filters` is config only. Each `show` knob goes with its `values` knob. If unset, nothing is filtered.
- `trafficFlowKnobIds` lists the ids, `TrafficFlowKnobId` is their union, and `TrafficFlowKnobValueOf<ID>` is the plain value one takes. The [modules guide](./modules.mdx#every-setting-as-data) describes the entry shape and its kinds.
- It leaves out `events`.
- The [traffic config playground](../../examples/traffic-config-playground) builds its flow and incidents controls from the two catalogues and sets each with [`setKnob`](./modules.mdx#setting-a-knob-by-its-id).

The Agent Toolkit sits between your application (chat UI and model provider) and the TomTom Maps SDK. Each user message
goes through two phases — intent classification, then a tool loop — and shared [state](./state.mdx) carries context
across turns.

## 1. Intent classification

Before the model sees any tool, one lightweight LLM call picks the tools this turn needs. Fewer tools in the request means
fewer wrong choices and fewer tokens.

- It reads each tool's `classificationPrompt` — a one-line "when to use me". A custom tool with one takes part
  automatically.
- It sees the last user message plus up to 8 earlier messages, each cut to 300 characters — never the system prompt,
  tool results or state.
- Tools with `alwaysActive: true` (`clarifyIntent` by default) are added every step, whatever the classifier picked.
- For *scopable* tools (`analyseData`, `processData`, `clusterIncidents`, and custom tools with a `scopeSchema`) it also
  names the data kinds the turn touches, and the tool's schema shrinks to those kinds — see
  [Scope-aware data tools](./scope-aware-data-tools.mdx).
- If classification fails, every tool is offered (fail-open).

The default classifier reuses your main model. Give it a smaller one, or change how much history it sees:

```typescript
import { createMapAgent, createDefaultClassifier } from '@tomtom-org/maps-sdk-plugin-agent-toolkit';
import { openai } from '@ai-sdk/openai';

const agent = createMapAgent(map, {
    model: openai('gpt-4o'),
    classifier: createDefaultClassifier({
        model: openai('gpt-4o-mini'),
        maxHistoryMessages: 8,        // earlier messages sent (default 8)
        maxHistoryMessageLength: 300, // characters kept per earlier message (default 300)
    }),
});
```

Or turn it off — every tool is offered every turn, and scopable tools keep their full, unscoped schema:

```typescript
const agent = createMapAgent(map, {
    model: openai('gpt-4o'),
    classifier: false,
});
```

`classifier` also accepts your own function, `(context) => Promise<ClassificationResult | null>`; it receives the
messages and every tool's metadata, and returning `null` offers every tool.

## 2. Tool loop

The model calls tools — geocode, search, route, show on map — in sequence or in parallel until it can answer.

- Tools return compact summaries (ids, counts, names, status); the geodata stays in [state](./state.mdx).
- Results are stored as entries with stable ids (`places-3`, `routes-1`), and the model reads them back with
  `recallState`. That is why *"add a stop after the first one"* or *"what were those restaurants again?"* work turns
  later.
- The loop stops after `maxSteps` steps (default 10), or as soon as a tool with `endsTurnOnCall` is called.

The [tool registry](./tools.mdx) lists every tool.

### Hooking into the loop

| Option | Use it to |
|---|---|
| `prepareStep` | Run your own per-step logic; any `activeTools` it returns are intersected with the classifier's pick |
| `maxSteps` | Cap the steps per turn (default 10) |
| `providerOptions` | Pass provider settings such as reasoning effort to every step |
| `stepProviderOptions` | Return per-step provider settings from `{ activeTools, stepNumber }`, merged over `providerOptions` |
| `outputSchemas` | Set `false` for providers that reject structured tool outputs |
| `onToolExecute` | Observe each call's `toolName`, `durationMs`, `isError` and `errorMessage` |

```typescript
const agent = createMapAgent(map, {
    model: openai('gpt-5'),
    providerOptions: { openai: { reasoningEffort: 'low' } },
    // Think harder only on turns that write code.
    stepProviderOptions: ({ activeTools }) =>
        activeTools?.some((name) => name === 'analyseData' || name === 'processData')
            ? { openai: { reasoningEffort: 'medium' } }
            : undefined,
    onToolExecute: ({ toolName, durationMs, isError }) => console.log(toolName, durationMs, isError),
});
```

Run one turn at a time per agent: scoping rewrites the agent's shared tool objects each turn, and state belongs to the
agent too. Create one agent per concurrent conversation.

## Per-tool classification prompts

If a custom tool is offered too often, or not when it should be, tune its `classificationPrompt`:

```typescript
// Too broad — activates for any location question
classificationPrompt: 'Get fleet vehicle data.'

// Precise — activates only for explicit vehicle ID references
classificationPrompt: 'Locate a fleet vehicle by its ID (e.g. "TT-001"); not for general location queries.'
```

The system prompt never reaches the classifier, so an instruction there cannot make a tool available — the
[system prompt guide](./customizing-system-prompt.mdx) explains what to do instead.

## Observing classification

`onClassify` receives each turn's pick and per-tool scopes — `null` when the classifier failed open:

```typescript
const agent = createMapAgent(map, {
    model: openai('gpt-4o'),
    onClassify: (result) => {
        if (result) {
            console.log('Selected tools:', result.activeToolNames);
            console.log('Per-tool scopes:', result.toolScopes); // e.g. { analyseData: { kinds: ['places', 'routes'] } }
            console.log('Classification took:', result.timeMs, 'ms', result.usage.totalTokens, 'tokens');
        }
    },
});
```

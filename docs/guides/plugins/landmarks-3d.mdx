## Use cases

- City-scale 3D visualization - Recognizable buildings (stadiums, cathedrals, towers) appear as detailed meshes instead of plain extrusions.
- Blend with the base map - Landmarks take the look of the base map's 3D buildings and follow it as the map colours change, or wear a look of your own.
- Show landmarks as they are - Landmarks wear the colours of their own stone, brick and roofs, under the map's light.

## How it works

- A MapLibre custom layer fetches the landmark tiles covering the viewport and renders them with Three.js, lit to match the map style.
- The layer draws when the map draws and asks for a frame only when a tile arrives, so a still map stays idle. If you change a field on `landmarks.layer` yourself, call `map.mapLibreMap.triggerRepaint()`.
- The layer sits below the POI layer, so POI labels and icons draw over the meshes and roads stay below.
- Layers you add to a module with `beforeLayerConfig: 'poi'` go under the meshes too, even when you add them later. To draw a label over a landmark, place its layer at `'top'`.
- `Landmarks3D` leaves the base map's 3D buildings shown or hidden as they are. Basemap buildings that overlap a landmark carry `has_landmark`, and the plugin filters them out so they don't clip through the meshes.
- After `setStyle`, the plugin restores the layer, the filter and the look.
- The plugin builds the tile URL from the global `TomTomConfig` (`apiKey`, `commonBaseURL`). Behind a credentialed proxy, tile requests send cookies like every other SDK request. `withCredentials` overrides that.
- Three.js decodes KTX2 textures with the Basis Universal transcoder, two files the plugin ships beside its bundle: `basis_transcoder.js` and `basis_transcoder.wasm`. The plugin loads them with the first landmark tile, so no request goes to a CDN.
  - By default, Vite and webpack 5 emit the two files with your build, so they load from your app's host. A bundler that doesn't emit the files a `new URL('./file', import.meta.url)` names, such as Rollup or esbuild on its own, needs `transcoderPath`.
  - The Vite 7 dev server's pre-bundler moves the plugin away from the two files. Upgrade to Vite 8, or add the plugin to the `optimizeDeps.exclude` that the [project setup](../../introduction/project-setup.mdx#vite-projects) gives for the SDK: `exclude: ['@tomtom-org/maps-sdk', '@tomtom-org/maps-sdk-plugin-landmarks-3d']`.
  - Set `transcoderPath` to serve the Basis Universal transcoder from your own host. Copy the two files from the plugin's `dist` folder, as the [configuration](#configuration) shows.
  - A strict Content Security Policy needs `blob:` in `worker-src`, and the transcoder's host in `connect-src`: `'self'` by default, or the host `transcoderPath` names.

## Installation

<Blockquote>
    This plugin uses `@tomtom-org/maps-sdk`, `maplibre-gl` and `three` as peer dependencies. Install all three.
</Blockquote>

```bash
npm install @tomtom-org/maps-sdk maplibre-gl three @tomtom-org/maps-sdk-plugin-landmarks-3d
```

1. Follow the [SDK Project Setup](../../introduction/project-setup.mdx) to create a `TomTomMap`. Pitch the camera. From above, the meshes look flat.
2. Show the base map's 3D buildings, so the landmarks stand in a 3D city. Most standard styles ship the [`buildings3D` group](../map/base-map.mdx) hidden. Leave this step out for landmarks alone.
3. Create the plugin. Rendering starts once the map is ready, so there is nothing to await.

```javascript
import { BaseMapModule } from '@tomtom-org/maps-sdk/map';
import { Landmarks3D } from '@tomtom-org/maps-sdk-plugin-landmarks-3d';

await BaseMapModule.get(map, { groups: { buildings3D: { visible: true } } });
const landmarks = new Landmarks3D(map);
```

## Usage examples

### Set the look

The look of the landmarks is a set of knobs. Set the ones you want, and leave the others to the base map:

```javascript
import { resetKnob, setKnob } from '@tomtom-org/maps-sdk/map';
import { landmarks3DKnobCatalogue } from '@tomtom-org/maps-sdk-plugin-landmarks-3d';

landmarks.updateConfig({ color: '#c8b28a', opacity: 0.9 });               // the rest still follows the base map
setKnob(landmarks, landmarks3DKnobCatalogue, 'verticalGradient', false); // a value held as data
resetKnob(landmarks, landmarks3DKnobCatalogue, 'color');                 // back to the base map's colour
landmarks.resetConfig();                                                 // every knob back to the base map
```

- Each knob you leave unset follows the style's 3D buildings, so landmarks blend in. They keep following them through `setStyle` and whatever restyles them: the [map colours](../map/styling-map-colors.mdx) `colors.artificial` and `colors.land`, as a [borrowed look](../map/styling-borrowed-looks.mdx) does, or a paint property you set on `3D - Building` yourself.
- While a [`Buildings3D`](#3d-buildings) on the same map shows, the unset `color`, `opacity` and `minZoom` follow its buildings instead, which take the place of the style's. The unset `maxZoom` is then 22, `texture` is `detail`, and `verticalGradient` reports `false`, since its walls have no gradient.
- Every standard style but `streetSatellite` has 3D buildings to follow. On `streetSatellite`, and on a style of your own without them or with a value that isn't a single one, the knob takes the 3D building look of `streetLight`. Set `color` where that doesn't suit a dark style.
- `Landmarks3D` follows the same rules as a [map module](../map/modules.mdx#setting-a-knob-by-its-id). `applyConfig(config)` replaces every knob and `updateConfig(config)` the ones you name. For values held as data, `setKnob` and `setKnobs` check each one against `landmarks3DKnobCatalogue` first.
- `getKnob` returns the value in force: the one you set, otherwise the base map's. `getConfig()` returns only the knobs you set.

#### Knobs

| Knob | Values | Unset |
|---|---|---|
| `visible` | `true` or `false` | `true` |
| `color` | a CSS colour | the colour of the base map's 3D buildings |
| `texture` | `mask`, `detail` or `color`: what each landmark's own texture adds to its outline. `mask` adds nothing, `detail` adds its light and shade over `color`, and `color` draws its own colours in place of `color` | `mask`, or `detail` while a `Buildings3D` shows |
| `opacity` | 0 to 1 | the opacity of the base map's 3D buildings |
| `verticalGradient` | `true` or `false`: whether the walls darken towards the ground | as the base map's 3D buildings |
| `minZoom`, `maxZoom` | 0 to 22: the lowest and highest whole zoom levels the landmarks are drawn at | the zoom range of the base map's 3D buildings |

### Show the landmarks' own colours

Each landmark comes with a texture of its own stone, brick, roofs and windows. By default, the texture only carves the landmark's outline, and the `color` knob paints it. To draw the landmarks in their own colours, set `texture` to `color`:

```javascript
landmarks.updateConfig({ texture: 'color' });
```

- `color` draws each landmark with its own textures, lit by the style light's colour and intensity, as the 3D buildings around it are. `opacity` and `verticalGradient` still apply.
- The textures keep their daylight colours on a dark style. To dim or tint them for the night, set the styling module's [`view.light` knobs](../map/styling-globe-and-sky.mdx#the-light-on-3d-buildings), which light the 3D buildings too.
- `detail` keeps the `color` knob and adds the texture's light and shade over it, so the landmarks match the city around them and still show their facades.
- Under a [`Buildings3D`](#3d-buildings), the textures take its sun, its sky and its shadows instead. There, `detail` is as strong as `facade.intensity`.

### Terrain

Landmarks stand on [3D terrain](../map/terrain.mdx#3d-elevation) without any configuration. The plugin lowers each one onto the lowest ground under its footprint, so no wall floats above a slope. Landmarks follow the terrain as it loads or its exaggeration changes.

```javascript
import { TerrainModule } from '@tomtom-org/maps-sdk/map';
import { Landmarks3D } from '@tomtom-org/maps-sdk-plugin-landmarks-3d';

await TerrainModule.get(map, { elevation: { visible: true }, hillshade: { visible: true } });
const landmarks = new Landmarks3D(map);
```

### Toggle visibility

```javascript
landmarks.setVisible(false); // the same as landmarks.updateConfig({ visible: false })
landmarks.isVisible(); // false
```

### Several maps

Create one `Landmarks3D` per map. Each one loads the tiles of its own map's view:

```javascript
const landmarks = maps.map((map) => new Landmarks3D(map));
```

- Each map takes a WebGL context, and a browser allows only so many per page (16 in Chrome). To show more landmarks than maps, move the maps you have instead of creating new ones.
- With more than one map, Three.js warns about `Multiple active KTX2 loaders`. The landmarks still render.

To frame a tall landmark, aim the camera at its mid-height instead of its foot. Set `centerClampedToGround: false` on the map and give the camera an `elevation` in metres. MapLibre's `flyTo` and `easeTo` leave the elevation where it was, so move with `jumpTo`:

```javascript
const map = new TomTomMap({
    mapLibre: {
        container: 'map',
        centerClampedToGround: false,
        center: [2.2945, 48.8584],
        elevation: 165, // halfway up the Eiffel Tower
        zoom: 15.4,
        pitch: 60,
    },
});
new Landmarks3D(map);

map.mapLibreMap.jumpTo({ center: [-122.3493, 47.6205], elevation: 92 }); // on to the Space Needle
```

Aim at the ground again before the reader zooms in. MapLibre picks how detailed its tiles are from the camera's distance to the point it aims at, not to the streets. Closing in on a point halfway up a tower draws the streets in thousands of tiles, and the map stalls. On `pointerdown`, `wheel` and `keydown`, jump to the same view aimed at the ground under the middle of the screen, as the demo below does. Listen in the capture phase, so the jump comes before the gesture starts: a jump during a gesture cancels it.

### Configuration

Pass the knobs to start with in the constructor, alongside `withCredentials` and `transcoderPath`. The first sends cookies with each tile request, and follows the SDK's proxy configuration unless you set it.

```javascript
const landmarks = new Landmarks3D(map, { minZoom: 14, opacity: 1 });
```

To load the texture transcoder from your own host, copy `basis_transcoder.js` and `basis_transcoder.wasm` from `node_modules/@tomtom-org/maps-sdk-plugin-landmarks-3d/dist` there. Then set `transcoderPath` to the path you serve them at, ending in `/`:

```javascript
const landmarks = new Landmarks3D(map, { transcoderPath: 'https://assets.example.com/basis/' });
```

Landmark tiles exist at zoom 15 only. Below it, each view needs more of them: at zoom 13, 16 times as many, and more again on a pitched map. Keep `minZoom` close to 15, above all with several maps on a page.

## 3D buildings

`Buildings3D` draws the base map's buildings in 3D with Three.js. Their walls get windows, a sun or a moon casts shadows across the buildings and the streets, and the dark street and mono presets give some windows a glow from inside. It extrudes the buildings of the vector tiles your map already loads and makes no requests of its own. Unlike the landmarks, it's in [Public Preview](https://docs.tomtom.com/legal/public-preview) and works with any API key. Shadows reach 5 km from the map's centre and fade out on the streets before that, so in a steeply tilted view the farthest buildings stand unshadowed.

The playground below draws Manhattan's towers, with controls for their windows, colours, light and shadows, a style switch and a sun that crosses the day.

<GuideDemo demo="buildings-3d-plugin-playground" />

To add the buildings, create the class, with the knobs to start with if you like. Like `Landmarks3D`, it starts drawing once the map is ready:

```javascript
import { Buildings3D } from '@tomtom-org/maps-sdk-plugin-landmarks-3d';

const buildings = new Buildings3D(map, { facade: { pattern: 'office' } });
```

- While it shows, it takes the place of the style's own 3D buildings, so you don't need the `buildings3D` group. `buildings.setVisible(false)` gives the style's buildings their place back. The filter leaves `3D - Building` with nothing to query, so a [`buildings3D` scope](../map/user-events.mdx#using-basemapmodule-for-background-interactions) on `BaseMapModule` never fires, and the Three.js buildings are not interactive either.
- It comes back after `setStyle`, in the look of the new style.
- While a `Landmarks3D` on the same map draws its landmarks, it leaves out the buildings they replace.
- It draws those landmarks among its buildings, so they stand in the same city. They share its sun and sky, cast their shadows on the buildings and the streets and catch the buildings' ones, and take its wall colour, opacity and `minZoom` for the landmark knobs you leave unset. Their own stonework and windows show as facade detail, as strong as `facade.intensity`, with no gradient down the walls. Set the landmarks' `texture` to `color` to draw them in their own colours instead. Their walls mirror a little of the street and the sky, their darker windows the most, as much as `reflections.intensity` sets.
- Its light is its own `light` and `ambientLight` knobs. The styling module's [`view.light` knobs](../map/styling-globe-and-sky.mdx#the-light-on-3d-buildings) light the style's 3D buildings, which it hides, so they light nothing while it shows.
- It draws at sea level. On [3D terrain](../map/terrain.mdx#3d-elevation), hills cover the lower floors of the buildings that stand on them.

### Tune the buildings

The look of the buildings is a set of knobs, and a preset gives each one you leave unset its value. By default, the preset is `auto`, which follows the map style. Light styles and `streetSatellite` get a sun and glass that mirrors the street and the sky, and the dark street and mono styles get a moon and lit windows.

```javascript
import { setKnob } from '@tomtom-org/maps-sdk/map';
import { buildings3DKnobCatalogue } from '@tomtom-org/maps-sdk-plugin-landmarks-3d';

buildings.updateConfig({ facade: { pattern: 'glass' } });                 // every building in glass
setKnob(buildings, buildings3DKnobCatalogue, 'light.altitude', 12);      // a low sun with long shadows
buildings.updateConfig({ preset: 'streetDark' });                        // a night city on any map
buildings.resetConfig();                                                 // every knob back to the map style
```

- Walls take the style's 3D building colour of each kind of building, and follow the [map colours](../map/styling-map-colors.mdx) that restyle them, until you set `walls.color`. Roofs take a shade darker than the walls until you set `roofs.color`.
- Unset, `walls.color` reports the colour of the buildings of no named kind, and `roofs.color` the walls' colour, not the darker shade drawn.
- `streetSatellite` has no 3D buildings to take colours from, so its preset brings walls and roofs of its own.
- `Buildings3D` follows the same rules as a [map module](../map/modules.mdx#setting-a-knob-by-its-id). `getKnob` returns the value in force, the preset's one when unset, and `getConfig()` returns only the knobs you set.

#### Buildings knobs

| Knob | Values | Unset |
|---|---|---|
| `visible` | `true` or `false` | `true` |
| `preset` | `auto` or a standard style ID | `auto` |
| `opacity` | 0 to 1 | `1` |
| `minZoom` | 13 to 22 | `15` |
| `facade.pattern` | `mixed`, `residential`, `office`, `glass` or `plain`. `mixed` picks one by the building's height | `mixed` |
| `facade.intensity` | 0 (plain walls) to 1 | the preset's |
| `facade.floorHeightMeters` | 2.5 to 6: the height of one storey, which spaces the rows of windows | `3.4` |
| `walls.color`, `roofs.color` | a CSS colour | the style's 3D building colours |
| `windows.color` | a CSS colour | the preset's |
| `reflections.intensity` | 0 (matte) to 1: how much the window glass mirrors the street, the facades across it with their windows, and the sky, and catches the sun. The reflection slides across the glass as the camera moves. The street it mirrors takes the same sun and sky light, the sky glows on the sun's side, and panes in shadow lose the sun. Glass curtain walls reflect the most, and `ambientLight.color` is the sky they mirror | `0.7` |
| `litWindows.color`, `litWindows.fraction`, `litWindows.intensity` | a CSS colour, then the share and brightness of the windows lit from inside, 0 to 1 | the preset's, no lit windows on light styles |
| `light.direction`, `light.altitude` | 0 to 359 degrees clockwise from north, then 5 to 90 degrees above the horizon | the preset's |
| `light.color`, `light.intensity` | a CSS colour, then 0 to 1 | the preset's |
| `ambientLight.color`, `ambientLight.intensity` | the light from the sky, which lights the walls in shade: a CSS colour, then 0 to 1 | the preset's |
| `shadows.visible`, `shadows.intensity` | `true` or `false`, then 0 to 1 | the preset's |
| `roadLabels.occluded`, `pois.occluded` | `true` draws the road names, or the style's POIs, under the buildings, so a building that covers a label hides it. A hidden POI still keeps other labels off its place, and the labels moved under give way to the ones above them where they collide | `false` |

### With map effects and a map theme

The buildings and the landmarks pair with two other plugins. The [map effects plugin](./map-effects.mdx) makes lit windows glow and softens the city with distance, and the [map-theme plugin](./map-theme.mdx) gives the map colours the walls follow. The playground below circles the Empire State Building in eight looks, each setting the style, the colours, the buildings, the landmarks and the effects together:

<GuideDemo demo="cinematic-city-orbit" />

- [Bloom](./map-effects-bloom.mdx) brings out the lit windows of a dark preset.
- The [depth of field](./map-effects-depth-of-field.mdx) treats the map as flat, so each part of a tower takes the depth of the ground behind it on screen, and its top blurs with the far ground. To keep a landmark sharp, raise `depthOfField.focus` towards the far ground.
- Leave `walls.color` unset to have the walls follow the theme's `artificial` colour, and set the landmarks' `color` to make them stand out from the city.

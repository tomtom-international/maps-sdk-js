The Map Effects plugin adds **practical post-processing** to a `TomTomMap`: effects computed from the rendered map's own pixels rather than from its style. They work on every style, custom ones included, survive every style release, and cannot be reproduced by editing the style at all — MapLibre has no post-processing surface.

<GuideDemo demo="map-effects-playground" />

This guide covers setting the plugin up, how its knobs reach the map, and its catalogue. Each effect has a guide of its own:

| Guide | Covers |
| --- | --- |
| [Bloom](./map-effects-bloom.mdx) | Lit roads, traffic tubes and route lines glowing, and scoping the glow to the colours you name |
| [Depth of field](./map-effects-depth-of-field.mdx) | One band of distance held sharp on a tilted map, the rest defocused as a lens would |
| [Grade, tint, fog, edge blur and vignette](./map-effects-overlays.mdx) | Muting the base map under your data, depth and focus at the rim of the view |
| [Custom GPU passes](./map-effects-custom-passes.mdx) | Your own fragment shaders inside the effect chain, with every other effect working on their result |

## What it is for

Every effect is named by the problem it solves, and is off by default. The SDK ships practical foundations, not looks.

| Effect | Solves |
| --- | --- |
| [**Bloom**](./map-effects-bloom.mdx) | Emphasis on dark and driving styles: lit roads, traffic tubes and route lines glow |
| [**Grade**](./map-effects-overlays.mdx#muting-the-base-map-grade-and-tint) (brightness, contrast, saturation) and [**tint**](./map-effects-overlays.mdx#muting-the-base-map-grade-and-tint) | Muting the base map so your data overlay reads first — the other half of the [`data-viz` styling preset](../map/styling.mdx#presets) |
| [**Fog**](./map-effects-overlays.mdx#fog-or-edge-blur) | Depth: the rim recedes as if seen through air |
| [**Edge blur**](./map-effects-overlays.mdx#fog-or-edge-blur) | Focus: the rim loses its detail, keeping its colour |
| [**Depth of field**](./map-effects-depth-of-field.mdx) | Depth on a tilted map: one band of distance stays sharp, the rest defocuses |
| [**Vignette**](./map-effects-overlays.mdx#vignette) | Focus, by darkening or lightening the edges |

## Installation

```bash
npm install @tomtom-org/maps-sdk maplibre-gl @tomtom-org/maps-sdk-plugin-map-effects
```

`@tomtom-org/maps-sdk` and `maplibre-gl` are peer dependencies.

## Usage

```javascript
import { resetKnob, TomTomMap } from '@tomtom-org/maps-sdk/map';
import { effectKnobCatalogue, MapEffects } from '@tomtom-org/maps-sdk-plugin-map-effects';

const map = new TomTomMap({
    style: 'standardDark',
    mapLibre: {
        container: 'map',
        // Bloom, the depth of field, your own passes and capture all read the map canvas back;
        // MapLibre keeps it readable only when asked.
        canvasContextAttributes: { preserveDrawingBuffer: true },
    },
});

const effects = new MapEffects(map);

// A quiet base under your own data layers:
effects.updateConfig({ 'grade.saturation': 0.4, 'grade.brightness': 0.85, 'tint.opacity': 0.15 });

// Emphasis on a dark style — traffic tubes and lit roads glow:
effects.updateConfig({ 'bloom.intensity': 0.5, 'bloom.threshold': 0.6 });

resetKnob(effects, effectKnobCatalogue, 'bloom.intensity'); // one effect off
effects.resetConfig();                                      // everything off
```

One knob goes through the SDK's [`setKnob`, `getKnob` and `resetKnob`](../map/modules.mdx#setting-a-knob-by-its-id), as on a map module, with `effectKnobCatalogue`; `getKnob` reads the override, or the catalogue default. `updateConfig(settings)` sets several and keeps the rest, `applyConfig(settings)` replaces them all, `resetConfig()` turns everything off, and `getConfig()` returns the overridden knobs as a plain object.

`remove()` detaches the effects from the map, takes their layers out of the page and releases the WebGL context the chain holds — which matters because a browser caps how many a page may have, and the map already holds one.

Every one of them checks each value with the SDK's [`validateKnobValue`](../map/modules.mdx#setting-a-knob-by-its-id) before anything is touched: a refused value throws `RangeError`, an unknown id `Error`, and the picture never half-changes.

## How it renders

No effect knob writes the MapLibre style. The plugin has a catalogue of its own, shared with no module, and every effect reads the map's rendered pixels, so the knobs change the *frame* rather than what the map draws. The one link to the style is [`bloom.only`](./map-effects-bloom.mdx#scoping-bloom-by-colour), which keys on the colours the style paints for the [style colour knobs](../map/styling.mdx#the-knob-catalogue) it names, whichever module holds them:

Three kinds of layer, in one order. **A GPU chain** runs first, on the map's own pixels: a WebGL2 canvas under everything else, holding the picture the rest then read. It runs [your own passes](./map-effects-custom-passes.mdx) and the [depth of field](./map-effects-depth-of-field.mdx), ping-ponging between render targets so each pass reads what the one before left without the picture leaving the GPU. **[Overlays](./map-effects-overlays.mdx)** stack over that result — `backdrop-filter` for grade, fog and edge blur, a gradient for vignette, a flat layer for tint. **[Bloom](./map-effects-bloom.mdx)** is neither: a small canvas (a quarter of the pixels) redrawn from the finished artwork every frame and blended in `screen` mode, because a glow needs the original *and* its blur, which a `backdrop-filter` cannot give.

Two consequences of that order are worth knowing:

- **Bloom reads the chain's output, not the raw map.** A defocused highlight therefore glows as the wide soft disc a photograph gives it, rather than as the pinpoint it was before the lens reached it.
- **Capture runs the same chain**, at the requested pixel ratio, then composites the same overlays — one implementation rather than a live half and an export half.

The chain and bloom both redraw on the map's own `render` event, coalesced to one draw per animation frame: they are made out of the map's pixels, so a pan changes what they have to draw. The other overlays are CSS and need no redrawing at all.

The overlays never take pointer events and sit below the map's controls.

## The catalogue

`effectKnobCatalogue` lists every knob with kind, range, default and the use case it serves, as static data like the SDK's [`stylingFoundationsKnobCatalogue`](../map/styling.mdx#the-knob-catalogue); `getKnob(effects, effectKnobCatalogue, id)` reads the value in force. The playground above generates its panel this way.

| Knob | Range | Default |
| --- | --- | --- |
| `bloom.intensity`, `bloom.threshold` | 0–1 | 0 (off), 0.55 |
| `bloom.radius` (CSS px) | 2–40 | 12 |
| `bloom.only` | list of style colour knobs, groups and CSS colours | `[]` (the whole frame) |
| `bloom.onlyTolerance` | 0–1 | 0.15 |
| `grade.brightness`, `grade.contrast` | 0.5–1.5 | 1 |
| `grade.saturation` | 0–1.5 | 1 |
| `fog.intensity`, `fog.reach` | 0–1 | 0 (off), 0.4 |
| `edgeBlur.intensity` (CSS px), `edgeBlur.reach` | 0–30, 0–1 | 0 (off), 0.5 |
| `depthOfField.intensity` (CSS px) | 0–30 | 0 (off) |
| `depthOfField.focus` (0 = nearest, 1 = farthest shown), `depthOfField.band` | 0–1 | 0, 0.3 |
| `depthOfField.bokeh` | 0–1 | 0.5 |
| `tint.color`, `tint.opacity` | colour, 0–1 | `#1f2937`, 0 (off) |
| `vignette.intensity` (negative darkens, positive lightens), `vignette.reach` | −1–1, 0–1 | 0 (off), 0.45 |

## Capture

`capture({ pixelRatio })` renders the current view — map and effects — into one canvas. The map is re-rendered at the requested ratio (never resampled), read back once every tile is drawn, and restored to follow the device afterwards. MapLibre clamps to its `maxCanvasSize`, so measure the ratio you got from the returned canvas rather than assuming.

```javascript
const canvas = await effects.capture({ pixelRatio: 3 });
canvas.toBlob((blob) => upload(blob), 'image/png');
```

## Relation to the Styling Foundations module

The [Styling Foundations module](../map/styling.mdx) changes the *style* — what the map draws. Effects change the *frame* — how the drawn map looks. They compose: the `data-viz` [map preset](../map/styling.mdx#presets) quiets the map's content; `grade.saturation` and `tint.opacity` mute what remains.

The Map Theme plugin themes a `TomTomMap` from **any source of a look**, such as a brand's swatches, your page's CSS, a logo, a photo, a mood or an artist. It turns the source into the ten [map colours](../map/styling-map-colors.mdx#map-colours-setmapcolors) for land, water, roads and labels, plus the [accent](../map/styling-map-colors.mdx#the-accent-what-a-theme-reaches-beyond-the-base-map) that routes, geometries and pins take. `setMapColors` applies them to the whole map.

## What it is for

Every source comes down to a handful of colours, and one call assigns them their roles:

| The look comes from | Call |
| --- | --- |
| A brand guide, a palette, colours a user picked | [`deriveMapColors(colors)`](#from-colours) |
| Your own page's CSS | [`deriveMapColors`](#from-your-pages-css) over its custom properties |
| A stylesheet: a website's, a design system's tokens | [`deriveMapColorsFromCss(cssText)`](#from-a-stylesheet) |
| A logo, a photo, a poster | [`deriveMapColorsFromImage(image)`](#from-an-image) |
| A mood, an artist | a coding agent or the Agent Toolkit writes the colours, [then `deriveMapColors`](#from-a-mood-an-artist-or-a-website-you-cannot-read) |

## Installation

```bash
npm install @tomtom-org/maps-sdk maplibre-gl culori @tomtom-org/maps-sdk-plugin-map-theme
```

`@tomtom-org/maps-sdk` and `culori` are peer dependencies. Every function is pure. Deriving needs no backend and no map.

## From colours

```javascript
import { StylingFoundationsModule } from '@tomtom-org/maps-sdk/map';
import { deriveMapColors } from '@tomtom-org/maps-sdk-plugin-map-theme';

const styling = await StylingFoundationsModule.get(map);
const colors = deriveMapColors(['#1d3f8a', '#e63312', '#f5d000', '#111111', '#f4f1ea']);
styling.setMapColors(colors);
```

- Every role comes back, including the accent, so a UI can show what became what. `setKnob(styling, stylingFoundationsKnobCatalogue, 'colors.water', …)` corrects one.
- An applied theme lives in the `colors.*` knobs of the [Styling Foundations module](../map/styling-map-colors.mdx#map-colours-setmapcolors). It survives `setStyle` and serialises with `getConfig()`.
- To [theme the base map alone](../map/styling-map-colors.mdx#the-accent-what-a-theme-reaches-beyond-the-base-map), leave `accent` out of the object before `setMapColors`.

## How colours get their roles

The assignment is deterministic. Order doesn't matter, and near-duplicates count once.

| Role | Gets |
| --- | --- |
| `land` | The lightest low-saturation colour (the darkest on a dark theme), toned down to a neutral |
| `roadMajor` | The most colourful (highest OKLCH chroma) colour, preferring one that isn't blue or green |
| `water`, `vegetation` | A blue or cyan, and a green |
| `label` | The colour contrasting most with `land`, if it reaches 4.5:1 |
| `accent` | The most colourful colour left that reads 3:1 on `land` and sits 30° of hue or more from `roadMajor`. Otherwise, `roadMajor`'s complement |

- Roles no colour fits are derived from `land`. Roads and outlines become shades of it, and water and vegetation muted hues. One to eight colours always give a complete palette, and picked colours come back as given.
- `mode` is `'auto'` (the default), `'light'` or `'dark'`, listed in `mapThemeModes`. `'auto'` makes a dark theme when the colours are mostly dark. The other two force their theme.

## Light and dark styles

`setMapColors` re-derives each style's own shades at that style's offsets, so a dark theme over `streetLight` pushes them to black. `mapColorsLightDark(colors)` tells a dark theme (labels lighter than land) from a light one, whether `'auto'` or the source decided it. Use it to switch the map first:

```javascript
import { mapColorsLightDark } from '@tomtom-org/maps-sdk-plugin-map-theme';

const lightDark = mapColorsLightDark(colors);
if (lightDark !== map.styleLightDarkTheme) {
    await map.setStyle(lightDark === 'dark' ? 'streetDark' : 'streetLight');
}
styling.setMapColors(colors);
```

## From your page's CSS

To give a map your app's brand, read the page's custom properties and its `theme-color`, and theme from those.

```javascript
const css = getComputedStyle(document.documentElement);
const brand = ['--color-primary', '--color-accent', '--color-surface', '--color-text']
    .map((name) => css.getPropertyValue(name).trim())
    .concat(document.querySelector('meta[name="theme-color"]')?.content ?? [])
    .filter(Boolean);

styling.setMapColors(deriveMapColors(brand));
```

Use your design system's own property names. The plugin reads colours in hex, `rgb()`, `hsl()` or a CSS name, and skips anything else.

## From a stylesheet

A whole stylesheet works too, such as a website's CSS, a design system's tokens or a file a user uploads. `deriveMapColorsFromCss(cssText, { mode, colorCount })` reads the colours it paints with and assigns them roles. It takes the CSS as text, so it needs no DOM.

```javascript
import { deriveMapColorsFromCss } from '@tomtom-org/maps-sdk-plugin-map-theme';

// A File from an <input type="file" accept=".css">, or CSS a server fetched
styling.setMapColors(deriveMapColorsFromCss(await fileInput.files[0].text()));
```

- The most used colour wins. A colour counts every time a rule fills with it. Borders and shadows count for less. Translucent colours, a colour's own shades (a button's hover) and words in `url()` paths don't count.
- `var()` resolves as the page does, against the rule's own custom properties or the page root's, not one set on another selector (`.inverse { --bg: … }`).
- Greys don't crowd out the brand. While colourful ones remain, the six colours (`colorCount` changes that) hold at most two greys, a background and a text colour.
- The theme is light or dark like the background on `:root`, `html` or `body`, or else the grey most rules fill with. It is light when neither resolves. Rules for one colour scheme (`prefers-color-scheme`, a `.dark` or `.light` class, `data-theme="dark"`) are read only with that `mode`, and then override the defaults. `'auto'` reads the page without them.
- `@import`s are not followed, so concatenate the files first.

`cssColors(cssText)` returns the colours, most used first, without assigning roles, so the user can edit them first.

## From an image

```javascript
import { deriveMapColorsFromImage } from '@tomtom-org/maps-sdk-plugin-map-theme';

// A File from an <input type="file">, a Blob, an <img>, an ImageBitmap or a CORS-readable URL
styling.setMapColors(await deriveMapColorsFromImage(fileInput.files[0], { mode: 'dark' }));
```

- The image is drawn into a 64×64 canvas, cheaply and in the browser, and its six dominant colours (`colorCount` changes that) get the roles. A small but striking colour can go missing.
- A URL must be served with `Access-Control-Allow-Origin`. Otherwise, pass the `File` or `Blob`.
- Without a DOM (a worker, a test, a server), decode the image yourself and pass `{ data, width, height }` (`ImagePixels`, shaped like `ImageData`). Or hand `dominantColors(pixels)` to `deriveMapColors`.
- Busy photos average into muted colours. Raise `colorCount`, or pick from `dominantColors` by hand.

## From a mood, an artist or a website you cannot read

A mood has no colours to read, and a page can't fetch another origin's CSS (a server can, and hand it to [`deriveMapColorsFromCss`](#from-a-stylesheet)). So these start with a model, not a function:

- A coding agent reads the site's `theme-color`, `:root` custom properties and logo, or turns "warm earthy tones" or "like a Miró" into three to six hex colours. It then writes the `deriveMapColors` call. The `/tomtom-maps-sdk-js` skill has the recipes.
- In a conversation, the [Agent Toolkit](./agent-toolkit/overview.mdx)'s `setMapStyling({ theme: { colors } })` does the same at run time, and `theme: { imageUrl }` themes from an image. It switches to the light or dark variant of the standard style the theme needs.

## Limits

- The assignment is a heuristic. It makes calls a designer wouldn't, which is why every role comes back for correction.
- Only the label contrast is guaranteed. A palette of near-equal lightness gives roads barely separable from land. A label derived for a mid-lightness land takes whichever side reads, even against the `mode`.
- If they find no colour that parses, or none that is opaque, `deriveMapColors` and `deriveMapColorsFromCss` throw a `RangeError`, and `deriveMapColorsFromImage` rejects with one. An image that can't be read (not CORS-readable, no DOM to decode it) rejects too. Catch the error to keep the current colours.
- A theme recolours a TomTom style. It sets the ten map colours and the accent, and leaves single layers as the style draws them. [Editing style layers](../map/styling-layers.mdx) covers those.
